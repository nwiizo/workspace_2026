# Addon: Multitenancy

> 「最も良いマルチテナントは、テナントが**自分が一人で使っている**と感じる」

マルチテナント設計、隔離、ノイジーネイバー対策のアドオン。

---

## 1. 中核概念

### 1.1 隔離レベルの階層

```
┌─────────────────────────────────────────────────┐
│ Level 5: 別アカウント / 別組織                   │  最強・最高コスト
│ Level 4: 別クラスタ                              │
│ Level 3: 別ネームスペース + ネットワークポリシー │
│ Level 2: 同一ネームスペース + クォータ           │
│ Level 1: 共有プロセス / マルチテナント DB        │  最弱・最低コスト
└─────────────────────────────────────────────────┘
```

選択は **規制要件 × コスト × 運用負荷** の三角形で決まる。

### 1.2 ノイジーネイバーの 4 形態

| 形態 | 例 |
|---|---|
| CPU / メモリ | 1 テナントが全クラスタの CPU を食う |
| ネットワーク | 1 テナントの帯域使い込みで全体遅延 |
| ストレージ IOPS | 共有 DB の IOPS 枯渇 |
| コントロールプレーン API | API rate limit の枯渇 |

**最も見えにくいのは CP API のノイジーネイバー**。
リソース増えても気づかれない。

### 1.3 公平性メカニズム

| メカニズム | 説明 |
|---|---|
| リソースクォータ | 上限設定 |
| プライオリティクラス | 重要度による排除順 |
| フェアキューイング | ラウンドロビン的処理 |
| バックプレッシャー | 上流から圧をかけて落ち着かせる |

## 2. 追加リソースとイベント

### 2.1 追加リソース

| リソース | 説明 |
|---|---|
| 隔離強度 | テナント間の隔離レベル平均 |
| 公平性スコア | リソース消費の偏り具合（低いほど偏り大） |
| ノイジーネイバー件数 | 月次発生数 |

### 2.2 追加修正値

| 修正源 | 範囲 |
|---|---|
| クォータ + プライオリティ両方設定 | +2 |
| 観測でノイジーネイバー即座検知可能 | +1 |
| 全テナント同レベル隔離（無差別） | -1 |
| クォータなしの共有運用 | -2 |

### 2.3 追加気候イベント

| D6 | 気候 | 内容 |
|---|---|---|
| 1 | ノイジーネイバー大発生 | 1 テナントが全体を停止寸前まで圧迫 |
| 2 | 規制要件追加 | 特定テナントの隔離強化要求 |
| 3 | コスト按分要求 | 「うちのコスト、いくら？」が複数から |
| 4 | テナント数急増 | 新規 10 テナント同時オンボード |
| 5 | クォータ違反多発 | 利用者から「足りない」苦情 |
| 6 | 平穏 | 全テナント穏当な利用 |

## 3. NPC

### 3.1 マリオ（マルチテナントアーキテクト・新規）

- 役割: 元 SaaS インフラ。マルチテナント設計のベテラン
- セリフ:
  - 「隔離は哲学。共有は経済。両立は技術」
  - 「ノイジーネイバーは検知できなければ存在しないのと同じ」
- 特殊能力 **〈隔離設計〉**: 関係値 +2 で、ノイジーネイバー気候 -50%

### 3.2 ケンジ（メインから）

最も「うるさいテナント」になる可能性のある利用者。
彼を隔離するか、公平性で対応するかが問われる。

### 3.3 タクヤ（メインから・SRE リード）

ノイジーネイバー検知と対応の現場責任者。

## 4. シナリオ 0: 学習モード

3 ターン。最初のクォータを 1 セット設計する。
学習補正 +2。

```
T0: マリオ「最初のクォータ設計、どのテナントで試します？」
  A) 新規参加チーム（小規模、影響少）
  B) Payments（影響力大、慎重）
  C) Analytics（重い処理多い）
```

---

## 5. シナリオ 1: 初期マルチテナント設計 （★★）

8 ターン。最初の隔離レベルを決め、5 テナントを乗せる。
- 隔離レベル選択
- クォータ初期値設計
- 監視の組み込み
- テナントオンボーディング

---

## 6. シナリオ 2: ノイジーネイバー対応 （★★★）

10 ターン。1 テナントが他を圧迫し始めた。
- 検知と告知
- 短期対応 vs 長期設計改修
- 関係を壊さずに「制限」を導入する

---

## 7. シナリオ 3: 50 テナント時代 （★★★★）

12 ターン。隔離戦略を再設計する大改修。
- マルチクラスタ移行
- 規制テナントの分離
- コスト按分との統合

## 8. バッドエンディング（7 種）

### 8.1 BAD-MT1: 共有死（技術軸）

> 終局条件: 隔離強度低 + 大規模ノイジーネイバー + 全社停止

```
1 つのテナントの暴走で、すべてが止まった。
共有 DB の IOPS 枯渇。全テナントの API が応答しない。
復旧に 6 時間。

「効率のための共有」は、「全員の死」になった。
```

### 8.2 BAD-MT2: クォータ地獄（技術軸）

> 終局条件: クォータ違反苦情 多 + クォータ調整チケット 殺到

```
クォータが厳しすぎた。
毎週 30 件の「クォータ上げて」チケット。
プラットフォームチームは、クォータ調整係になった。

クォータは制御ではなく、官僚機構の道具になった。
```

### 8.3 BAD-MT3: 規制テナント漏洩（技術軸）

> 終局条件: 規制テナント分離不十分 + データ越境疑い

```
監査で発覚した:
規制要件のあるテナントのデータが、共有ログに混在していた。
故意ではなかった。設計が甘かっただけだった。

法務とコンプライアンスが大規模対応に入った。
プラットフォーム全体の信頼が、揺らいだ。
```

### 8.4 BAD-MT4: テナント差別文化（組織軸）

> 終局条件: テナント間優先度の不公平 + 苦情多発

```
「Payments チームは優遇されている」
「うちは後回しにされている」

優先度設計が、組織の政治を反映してしまった。
プラットフォームは、公平な基盤ではなく、権力構造のミラーになった。
```

### 8.5 BAD-MT5: マリオ離反（組織軸）

> 終局条件: マリオ関係値 ≤ -1 + 隔離設計強行変更

```
マリオが言った。「設計の理由を聞かないなら、私は要らない」

そして去った。
隔離戦略は、その後、首尾一貫しないものになった。
ノイジーネイバーは、原因が判明する前に対応された。
原因の特定が、誰にもできなくなった。
```

### 8.6 BAD-MT6: 隔離コスト破綻（経営財務軸）

> 終局条件: 隔離レベル過剰 + クラウドコスト爆発

```
すべてのテナントを別アカウントに分けた。
監査も簡単。隔離も完璧。

そして、クラウド費は 2.5 倍になった。
共有による効率は、消えた。
経営は「逆ROI」と呼んだ。
```

### 8.7 BAD-MT7: 「うちは特別」病（文化軸）

> 終局条件: 例外テナント ≥ 5 + 標準運用形骸化

```
「うちは特別だから例外で」
「うちもです」

例外が常態化した。
標準運用は、もはや誰も使わない、誰の事情も反映しない、空虚な型だった。
```

### 8.8 BAD-MT未確定

組織固有のマルチテナント失敗が描写される。

## 9. グッドエンディング（4 種）

### 9.1 GOOD-MT1: 静かな隔離（技術軸）

> 達成条件: ノイジーネイバー全社影響 0 が 6 ヶ月継続

```
ノイジーネイバーは検知されていた。
ただ、自動的に分離され、他テナントには波及しなかった。

テナントは、自分が一人で使っているかのように感じていた。
それは技術の勝利だった。
```

### 9.2 GOOD-MT2: 公平性の証明（技術軸）

> 達成条件: テナント間公平性スコア ≥ 90 + 苦情少

```
50 テナントが共存していた。
誰も「不公平だ」と言わなかった。

データが語っていた:
リソース使用量は事業規模に比例し、応答時間はすべて SLO 内だった。
公平性は、感情ではなく数字だった。
```

### 9.3 GOOD-MT3: 隔離 ROI 達成（経営財務軸）

> 達成条件: 隔離コスト / 全クラウド費 ≤ 15% + 規制対応 完了

```
規制要件は満たされていた。
共有による効率は、85% 維持されていた。

「過剰な隔離 = 高コスト」ではなく、
「適切な隔離 = 賢いコスト」が、実装されていた。
```

### 9.4 GOOD-MT4: 「みんなのプラットフォーム」（文化軸）

> 達成条件: テナント間の協調学習が発生

```
1 つのテナントが「うちのリソース使い方、こうしたら上手くいった」と共有した。
他のテナントが「私たちも」と続いた。

共有基盤は、技術だけでなく、知識を共有する場になった。
```

# Addon: AI-Augmented Platform

> 「AI を組み込んだプラットフォームは、賢くなる。
>  ただし、賢いだけで信頼できるとは限らない。
>  信頼は、別の章で稼ぐ必要がある」

AI 拡張プラットフォーム、自己進化、推論コストを扱うアドオン。

---

## 1. 中核概念

### 1.1 AI 拡張の 5 レベル

```
Lv0  人間のみ          意思決定はすべて人が行う
Lv1  サジェスト         AI が選択肢を提示、判断は人
Lv2  下書き             AI が初版を作り、人が校正
Lv3  共同操縦           特定領域は AI が自律、例外は人にエスカレート
Lv4  オートパイロット   通常運用は AI、戦略のみ人が方向付け
Lv5  自己進化           AI が学習し、自分自身の能力を改善
```

実用ゾーンは Lv1-Lv3。Lv4 以上は限定領域のみ。

### 1.2 拡張対象の選定

| プラットフォーム機能 | AI 拡張の妥当性 |
|---|---|
| ドキュメント検索 | ◎ 即効性高 |
| Runbook 自動生成 | ◎ 効果絶大 |
| 障害対応サジェスト | ○ ただし暴走に注意 |
| 自動コード変換 | ○ レビュー必須 |
| 自動コスト最適化 | △ 慎重に |
| 自律的本番変更 | × 現時点では避ける |

### 1.3 推論コストと精度

```
推論コスト
   ↑
   │     ●  GPT-4 級
   │    
   │   ●    GPT-3.5 / Haiku
   │  
   │ ●      自社 fine-tuned 小型モデル
   │●       RAG + 軽量モデル
   └───────────────→ 精度
```

「**精度 100% が必要かどうか**」が、モデル選定の核心。
ドキュメント検索なら 80% で十分。本番変更は 99.99% でも危険。

## 3. NPC

### 3.1 リュウ（AI プラットフォームエンジニア・新規）

- 役割: 元 ML エンジニア。PE と ML の融合を担う
- セリフ:
  - 「LLM はライブラリじゃありません。**確率的な同僚**です」
  - 「ガードレールの設計は、機能より先に来ます」
- 特殊能力 **〈確率設計〉**: 関係値 +2 で、AI 暴走気候 -50%

### 3.2 ハルカ（メインから・セキュリティ）

AI 機能のデータ取り扱い責任者として登場。

### 3.3 玲奈（メインから・CTO）

AI 投資 ROI の主たる質問者。

## 8. バッドエンディング（7 種）

### 8.1 BAD-AI1: ハルシネーション地獄（技術軸）

> 終局条件: ハルシネーション率 ≥ 10% + 利用者が誤対応

```
AI Q&A は確信を持って答えた。
半分は正しく、半分は嘘だった。
利用者は最初それを信じ、後で気づいた。

「AI は信用できない」が、組織の文化になった。
プラットフォーム全体が、AI のせいで信頼を失った。
```

### 8.2 BAD-AI2: AI 暴走による本番事故（技術軸）

> 終局条件: AI 自律機能が本番障害誘発

```
AI が「コスト最適化のため」インスタンスを止めた。
それは本番の主要サービスだった。

復旧 4 時間。
AI に与えた権限は、人間の判断より深刻な事故を起こした。
```

### 8.3 BAD-AI3: モデルロックイン（技術軸）

> 終局条件: 特定 LLM API 依存 + ベンダー変更で機能消失

```
すべての AI 機能が、特定 SaaS の API で動いていた。
ベンダーが価格改定、または機能終了した時、
あなたの AI 機能は一夜で消えた。

抽象化レイヤーは、後から追加するには遅すぎた。
```

### 8.4 BAD-AI4: AI 部門分断（組織軸）

> 終局条件: AI チームと PE チームの責任分界不明 + 連携崩壊

```
「AI 機能のバグはあっちのチーム」
「いや、それはプラットフォームの問題」

責任のグレーゾーンが拡大した。
障害時に誰が対応するか、毎回協議になった。
利用者は「結局誰の責任なんだ」と離れていった。
```

### 8.5 BAD-AI5: リュウ離反（組織軸）

> 終局条件: リュウ関係値 ≤ -1 + AI 戦略強行

```
リュウが言った。
「設計の前に機能を約束されても、私はできません」

そして去った。
組織内の AI 専門知識は消え、後任は採用に半年かかった。
AI 戦略は、停滞した。
```

### 8.6 BAD-AI6: 推論コスト破綻（経営財務軸）

> 終局条件: AI コスト ≥ プラットフォーム予算の 40%

```
利用増で AI コストが青天井になった。
1 ユーザーあたりの推論コストは、サブスク収益の 2 倍だった。

経営は AI 機能の停止を命じた。
利用者は「便利だったのに」と落胆した。
```

### 8.7 BAD-AI7: 「AI 神格化」文化（文化軸）

> 終局条件: AI 出力を盲信する文化 + 人間判断の劣化

```
組織内で、AI の答えは検証されずに使われるようになった。
「AI が言ってる」が、議論の終結点になった。
人間の専門性は、AI のラッパーになった。

3 年後、AI が間違えた時、それを正せる人がいなくなった。
```

### 8.8 BAD-AI未確定

組織固有の AI 拡張失敗が描写される。

## 9. グッドエンディング（4 種）

### 9.1 GOOD-AI1: 信頼できる共同操縦（技術軸）

> 達成条件: AI 機能が日常運用に統合 + 信頼度高 + 暴走 0

```
AI は、SRE の隣で働く同僚になった。
障害対応の初動を共にし、Runbook を提案し、しかし最終判断は人間に委ねる。

AI は、人を置き換えなかった。
人の判断を、より早く、より深くした。
```

### 9.2 GOOD-AI2: 自己進化への到達（技術軸）

> 達成条件: データ flywheel 確立 + AI 機能の精度継続改善

```
AI 機能は、使われるたびに賢くなった。
利用者のフィードバックが、自動的に次の改善になっていた。

プラットフォームは、もはや人間だけが進化させるものではなかった。
```

### 9.3 GOOD-AI3: 推論コスト最適化（経営財務軸）

> 達成条件: AI コスト / 価値 効率良 + 投資 ROI 高

```
推論コストは、機能毎に最適なモデルが選ばれていた。
ドキュメント Q&A は小型モデル、複雑判断は GPT-4。

コストは制御され、価値は最大化されていた。
CFO は「AI 投資、これは続けて欲しい」と言った。
```

### 9.4 GOOD-AI4: 「AI と私たち」文化（文化軸）

> 達成条件: 利用者が AI 機能を批判的に活用 + フィードバック増

```
利用者は AI の出力を盲信せず、ただし無視もしなかった。
「これは AI のサジェスト。検証して使う」が標準になった。

人と AI は、共生する仲間になった。
そして、その共生は、組織を強くしていた。
```

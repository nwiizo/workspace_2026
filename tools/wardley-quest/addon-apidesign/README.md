# API Design Quest

契約としてのAPI設計を学ぶアドオンクエスト。

## 概要

- APIを「チーム間の契約」として捉える
- 良いAPIの4つの柱（運用可能性・表現力・シンプル性・予測可能性）
- ドメインモデリングとAPI設計の関係
- バージョニング戦略と後方互換性
- エラーハンドリングの実装

## 対象者

- エンジニアとして実装力を磨きたい方
- API設計の原則を学びたい方
- ドメイン駆動設計をAPIで表現したい方

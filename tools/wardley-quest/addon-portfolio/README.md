# Portfolio Modernization Quest

[Strategic Evolution Quest](../) のアドオンシナリオ

戦略的ITポートフォリオ管理とモダナイゼーション戦略を学ぶRPG。Core Domain Chartを活用し、投資判断とロードマップ策定を実践します。

## 前提

**単体でもプレイ可能です。** [Strategic Evolution Quest](../) をプレイ済みだとより深く理解できます。

## 学べる概念

### Core Domain Chart

DDDに基づくドメイン分類フレームワーク：

| 分類 | 特徴 | 投資方針 |
|---|---|---|
| **Core** | 競争優位の源泉、差別化領域 | 最優先投資、内製維持、最高のチーム |
| **Supporting** | 必要だが差別化ではない | 必要最小限、効率化 |
| **Generic** | 業界で共通の機能 | 外部化・標準化、SaaS活用 |

### ユーティリティIT vs 戦略的IT

Martin Fowlerの二分法に基づく投資判断：

- **戦略的IT（5-20%）**: ビジネスの差別化に直接貢献 → 社内で構築、最高の人材
- **ユーティリティIT（80-95%）**: 差別化には貢献しないが必要 → 既製品、SaaS、最小コスト

### 6つのR戦略

モダナイゼーションアプローチの選択：

| 戦略 | 適用場面 |
|---|---|
| **Retire** | ビジネス価値なし、廃止 |
| **Retain** | 現状維持が最適 |
| **Rehost** | そのままクラウド移行 |
| **Replatform** | 一部最適化して移行 |
| **Refactor** | 根本的なアーキテクチャ改善 |
| **Replace** | SaaS/パッケージへ置換 |

### ストラングラーフィグパターン

レガシーシステムの段階的移行手法：

1. ファサードの導入
2. 機能の段階的移行
3. レガシーの削除

### 投資判断マトリクス

ビジネス価値と技術的健全性の2軸で判断：

| 象限 | 状態 | 戦略 |
|---|---|---|
| **Invest** | 健全で重要 | 積極投資 |
| **Transform** | 重要だが問題あり | 変革投資 |
| **Tolerate** | 健全だが重要度低 | 許容・効率化 |
| **Sunset** | 問題あり・重要度低 | 廃止 |

### イシュー選定の重要性

AI時代における「何を作るか」の本質的な問い：

> 「実装の壁が低くなったからこそ、何を作るかが重要」

- **技術的実現可能性と価値創造**: 作れることと作るべきことは異なる
- **イシューからはじめよ**: 解くべき問題の選定が最重要
- **機会コストの認識**: 投資しないことで失われる価値も評価

### AI時代のポートフォリオ管理

生成AIが変える投資判断の前提：

- **実装コストの劇的低下**: 従来は高コストだった開発が低コスト化
- **差別化領域の再定義**: 実装ではなく「何を作るか」が差別化に
- **スピードの価値向上**: 素早く仮説検証できる能力の重要性増大
- **技術的負債の質的変化**: AIが生成したコードの負債管理

## 想定される学習成果

- Core Domain Chartを使ったシステム分類能力
- 限られたリソースでの投資優先順位付け
- 6つのR戦略の使い分け判断力
- ステークホルダーを巻き込んだロードマップ策定

# 第1章: ゲーム概要

## 1.1 このゲームについて

**Discovery Workshop Quest** は、Strategic Evolution Questの拡張として、**ステークホルダー理解とドメイン発見のためのワークショップ手法を学ぶ**戦略シミュレーションRPGです。

モダナイゼーションや新規プロジェクトの成功は、最初の「発見」フェーズにかかっています。リスニングツアー、インパクトマッピング、リスクストーミングなどの手法を使いこなし、プロジェクトの成功確率を高めます。

### 核心的な問い

> **「何を作るか、なぜ作るか、誰のために作るかを、どうすれば正しく理解できるのか？」**

### Discoveryの重要性

| よくある失敗 | Discoveryで防げること |
|---|---|
| 「作ったけど使われない」 | ステークホルダーの真のニーズを理解 |
| 「想定と違った」 | 仮説を早期に検証 |
| 「後から大きな問題が」 | リスクの早期発見 |
| 「関係者が協力しない」 | 早期の巻き込みと合意形成 |
| 「ゴールがぶれる」 | 明確な成功基準の定義 |

## 1.2 Discovery手法の本質

### Nick Tuneの洞察

Architecture Modernizationでは、**技術的な決定の前に、ビジネスとステークホルダーを深く理解すること**の重要性が強調されています。

| 観点 | 説明 |
|---|---|
| **傾聴** | 答えを持っていく前に、問いを持っていく |
| **共感** | ステークホルダーの立場で考える |
| **発見** | 想定外のニーズや制約を見つける |
| **整合** | ビジネス目標と技術判断を結びつける |

### Discoveryで明らかにすべきこと

```
┌─────────────────────────────────────────────────────────────┐
│  Discoveryで答えるべき問い                                   │
│                                                             │
│  ビジネス:                                                  │
│  ・なぜこのプロジェクトを行うのか？                         │
│  ・成功とは何か？どう測定するか？                           │
│  ・ビジネス上の制約は何か？                                 │
│                                                             │
│  ステークホルダー:                                          │
│  ・誰が影響を受けるか？                                     │
│  ・彼らは何を求めているか？                                 │
│  ・誰がブロッカーになりうるか？                             │
│                                                             │
│  ドメイン:                                                  │
│  ・ビジネスはどう動いているか？                             │
│  ・どこに複雑さがあるか？                                   │
│  ・どこに暗黙知があるか？                                   │
│                                                             │
│  リスク:                                                    │
│  ・何がプロジェクトを失敗させうるか？                       │
│  ・技術的リスクは何か？                                     │
│  ・組織的リスクは何か？                                     │
└─────────────────────────────────────────────────────────────┘
```

## 1.3 ゲームの厳しさについて

このゲームでは以下のことが起こります：

| 現象 | 説明 | 学び |
|---|---|---|
| **隠れたステークホルダー** | 後から重要人物が登場 | ステークホルダーマッピングの重要性 |
| **本音と建前** | 公式な要求と実際のニーズが違う | 傾聴と観察の技術 |
| **政治的な罠** | 特定の人の意見を聞きすぎる | バランスの取れた情報収集 |
| **情報過多** | 聞きすぎて整理できない | 優先順位付けの技術 |
| **時間切れ** | 十分なDiscoveryができずに開始 | タイムボックスの管理 |
| **発見の無視** | 発見した情報が活用されない | 成果の文書化と共有 |

**これらは現実のプロジェクトで直面する課題です。**

## 1.4 用語集

### Discovery用語

| 用語 | 定義 |
|---|---|
| **リスニングツアー** | ステークホルダーを訪問して話を聴く活動。解決策を持っていく前に、まず「ヒアリング」から始める。 |
| **インパクトマッピング** | ビジネス目標から逆算して機能を導出する手法（Goal→Actor→Impact→Deliverable） |
| **リスクストーミング** | チームでリスクを洗い出すワークショップ。C4コンテナ図にリスクを付箋で貼り付ける。 |
| **ビジネスモデルキャンバス** | ビジネスの構造を1枚で可視化するツール |
| **プロダクトビジョンボード** | プロダクトの方向性を明確にするツール（ビジョン、ターゲット、課題、プロダクト、事業目標） |
| **ステークホルダーマップ** | 関係者の影響力と関心度を可視化 |
| **AMET** | Architecture Modernization Enabling Team。モダナイゼーションを主導するチーム。 |
| **キックスターターワークショップ** | モダナイゼーションの第一歩を決定・設計する3日間の集中討議 |
| **デザイン・スクイグル** | デザインプロセスの混沌とした予測不可能な性質を表現したモデル |
| **ダブルダイヤモンド** | 発見→定義→開発→提供の発散と収束を繰り返すデザインプロセス |

### 質問形式用語

| 用語 | 定義 |
|---|---|
| **文章完成法** | 「今、私の仕事で腹が立っていることの1つは、______なことです」のように空欄を埋めさせる |
| **感情選択法** | 感情の環を見せ、特定テーマについて自分の気持ちを表す感情を選んでもらう |
| **画像選択法** | 写真やイラストから自分の気持ちを表す画像を選んでもらう |
| **最悪のシナリオ法** | 「考えうる限り最悪のビジネスチャンスとは何か？」のように逆方向から考えさせる |
| **悪魔の代弁者法** | 相手の信念に対して建設的に異議を唱え、思考を深める |
| **5回のなぜ** | 「なぜ？」を繰り返して根本原因にたどり着く手法 |

### ワークショップ用語

| 用語 | 定義 |
|---|---|
| **ファシリテーター** | ワークショップを進行する人 |
| **タイムボックス** | 活動に割り当てる時間の枠 |
| **パーキングロット** | 後で議論するトピックの一時置き場 |
| **ドットボーティング** | 付箋にシールを貼って優先順位を決める手法 |

### ゲーム用語

| 用語 | 定義 |
|---|---|
| **ターン** | 1セッション/1日相当 |
| **発見ポイント** | 重要な洞察の獲得量 |
| **ステークホルダー信頼度** | 関係者からの信頼レベル |
| **リスク可視化度** | リスクの把握度合い |
| **整合性** | ビジネス目標との整合度 |

## 2.2 判定システム

### 基本判定（2D6）

| 出目 | 結果 | 効果 |
|:---:|---|---|
| 2 | **致命的失敗** | 信頼喪失。重要情報へのアクセス遮断。 |
| 3-4 | **失敗** | 時間を浪費。有用な情報なし。 |
| 5-6 | **部分的失敗** | 表面的な情報のみ。深い洞察なし。 |
| 7-8 | **部分的成功** | 基本情報を取得。追加確認が必要。 |
| 9-10 | **成功** | 重要な発見。次の手がかりを得る。 |
| 11 | **大成功** | 画期的な洞察。隠れた情報を発見。 |
| 12 | **完全成功** | 期待以上の成果。信頼関係も強化。 |

### 修正値

#### インタビュー関連

| 状況 | 修正 | 根拠 |
|---|:---:|---|
| 事前準備が十分 | +2 | 的確な質問ができる |
| オープンな質問を使用 | +1 | 深い情報を引き出す |
| 傾聴の姿勢 | +1 | 信頼を築く |
| 紹介者がいる | +1 | 初対面の壁を越える |
| 準備不足 | -2 | 時間を無駄にする |
| 誘導的な質問 | -1 | バイアスがかかる |
| 一方的に話す | -2 | 相手が閉じる |

#### ワークショップ関連

| 状況 | 修正 | 根拠 |
|---|:---:|---|
| 適切なフレームワーク選択 | +2 | 効率的な議論 |
| 参加者が適切 | +1 | 必要な視点が集まる |
| タイムボックス管理 | +1 | 集中した議論 |
| フレームワーク不適切 | -2 | 時間の浪費 |
| 重要な参加者不在 | -2 | 情報の欠落 |
| 時間超過 | -1 | 疲労と集中力低下 |

#### 組織関連

| 状況 | 修正 | 根拠 |
|---|:---:|---|
| 経営層のスポンサーシップ | +2 | アクセス権確保 |
| 部門横断の協力 | +1 | 多角的視点 |
| 信頼関係構築済み | +1 | 本音を聞ける |
| 政治的な壁 | -2 | 情報遮断 |
| 部門のサイロ化 | -1 | 断片的情報 |

## 2.3 状況イベント

毎ターン開始時にD6を2回振り、2つのイベントが発生します。

### 状況イベント表

| D6 | イベント | 効果 | 対応のヒント |
|:---:|---|---|---|
| 1 | **隠れたステークホルダー** | 重要な関係者の存在が判明。彼らへのアプローチが必要。 | ステークホルダーマップ更新 |
| 2 | **矛盾する情報** | 異なる部門から相反する情報。真実を見極める必要。 | 追加確認、三角測量 |
| 3 | **アクセス制限** | 一部の情報や人へのアクセスが制限される。 | 別ルート、スポンサー活用 |
| 4 | **時間圧力** | 経営層から「早く結論を」プレッシャー。 | スコープ調整、優先順位 |
| 5 | **本音の吐露** | ステークホルダーが本音を話してくれる機会。 | 深掘りのチャンス |
| 6 | **予期せぬリスク発見** | 重大なリスクが見つかる。 | リスク評価、報告 |

### 常時適用パターン

| パターン | 効果 |
|---|---|
| **最初に聞いた人の意見に引っ張られる** | 確証バイアスに注意 |
| **本音は簡単には出ない** | 信頼構築に時間がかかる |
| **書かれていないルールがある** | 暗黙知を見逃さない |
| **誰もが自分の視点で語る** | 複数の視点で検証 |
| **時間は常に不足する** | 優先順位が重要 |

# 第3章: リスニングツアー

## 3.1 概要

リスニングツアーは、**ステークホルダーを訪問して直接話を聴く**活動です。

### このフレームワークで答える問い

- 「この人は何を気にしているか？」
- 「彼らにとっての成功とは何か？」
- 「彼らが抱える課題は何か？」
- 「誰が重要な情報を持っているか？」

## 3.3 進行のコツ

### インタビューの原則

| 原則 | 説明 |
|---|---|
| **傾聴** | 話すより聴く（80:20の法則） |
| **沈黙** | 相手が考える時間を与える |
| **メモ** | 後で詳細を書き起こすために記録 |
| **確認** | 理解が正しいか確認する |
| **感謝** | 時間を取ってくれたことへの感謝 |

### 避けるべきこと

| 避けること | 理由 |
|---|---|
| 誘導質問 | 答えを誘導してしまう |
| 専門用語 | 相手が理解できない可能性 |
| 判断を示す | 相手が萎縮する |

# 第4章: インパクトマッピング

## 4.1 概要

インパクトマッピングは、**ビジネス目標から逆算して、何を作るべきかを導出する**手法です。

### 4つの質問

```
┌─────────────────────────────────────────────────────────────┐
│  インパクトマッピングの構造                                  │
│                                                             │
│  WHY ───→ WHO ───→ HOW ───→ WHAT                           │
│  目標      アクター   インパクト   成果物                    │
│                                                             │
│  ┌─────┐   ┌─────┐   ┌─────┐   ┌─────┐                    │
│  │Goal │→  │Actor│→  │Impact│→ │Deliv│                    │
│  │     │   │     │   │      │   │erable│                   │
│  └─────┘   └─────┘   └─────┘   └─────┘                    │
│                                                             │
│  WHY: なぜこれをやるのか？（ビジネス目標）                  │
│  WHO: 誰がこの目標達成に関与するか？                        │
│  HOW: 彼らの行動をどう変えるか？                            │
│  WHAT: その変化を引き起こすために何を作るか？               │
└─────────────────────────────────────────────────────────────┘
```

---

## 4.2 進め方

### ステップ1: 目標の明確化

```
良い目標の例:
・「新規顧客獲得を20%増加させる」
・「処理時間を50%短縮する」
・「顧客満足度をNPS+30にする」

悪い目標の例:
・「新しいシステムを作る」← これは手段
・「モダナイズする」← 測定できない
```

### ステップ2: アクターの特定

```
誰がこの目標達成に影響するか？

・目標を達成する人
・目標達成を妨げる人
・目標達成を助ける人
・間接的に影響する人
```

### ステップ3: インパクトの定義

```
彼らの行動をどう変えたいか？

・何かを「始める」
・何かを「やめる」
・何かを「もっとする」
・何かを「減らす」
```

### ステップ4: 成果物の導出

```
その行動変化を引き起こすために何を作るか？

インパクトから逆算して機能を考える
優先順位は目標への貢献度で決める
```

---

## 4.3 判定への影響

| 状況 | 判定修正 |
|---|:---:|
| 測定可能な目標を設定 | +2 |
| 複数のアクターを特定 | +1 |
| インパクトを具体的に定義 | +1 |
| 目標が曖昧 | -2 |
| アクターが不明確 | -1 |

| **信頼構築マスター** | 5 | 全ての関係構築アクションで信頼度+1（永続） |
| **ファシリテーションマスター** | 5 | 全てのワークショップアクション判定+2 |
| **インサイト抽出** | 5 | 発見ポイント獲得時、1.5倍（端数切り上げ） |

## 10.4 マイルストーンシステム

条件を達成するとマイルストーンを獲得し、報酬を得られます。

### 基本マイルストーン

| マイルストーン | 条件 | 報酬 |
|---------------|------|------|
| **初めてのインタビュー成功** | 1on1インタビューで成功判定 | 次のインタビュー判定+1 |
| **ステークホルダーマップ完成** | 全主要ステークホルダーを特定 | 「隠れたステークホルダー」イベント時のヒント |
| **本音を引き出した** | 信頼度+3のNPCから情報取得 | 称号「傾聴者」、信頼構築判定+1（永続） |
| **リスク先読み** | リスクストーミングで重大リスクを事前特定 | 洞察ポイント+2 |
| **合意形成達成** | 対立する部門間で合意を形成 | 称号「調停者」、ワークショップ判定+1（永続） |

### 応用マイルストーン

| マイルストーン | 条件 | 報酬 |
|---------------|------|------|
| **暗黙知の可視化** | 暗黙知を3つ以上発見 | 称号「ドメインハンター」、洞察ポイント+3 |
| **全員味方** | 全NPCとの関係値を+2以上に | 称号「信頼の構築者」、NPC関連判定+1（永続） |
| **完璧なDiscovery** | 発見ポイント25以上でクリア | 称号「Discoveryマスター」、次回ゲーム開始時洞察ポイント+2 |
| **時間厳守** | タイムボックスを一度も超過せずクリア | 称号「タイムキーパー」、時間圧力イベントのペナルティ軽減 |
| **危機回避** | 重大リスクを全て事前対処 | 称号「リスクハンター」、リスク関連判定+1（永続） |

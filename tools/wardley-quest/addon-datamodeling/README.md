# Data Modeling Quest

[Strategic Evolution Quest](../) のアドオンシナリオ

DDDに基づくデータ設計RPG。境界づけられたコンテキストをデータモデルとして実装する方法を学びます。

## 前提

**単体でもプレイ可能です。** [Strategic Evolution Quest](../) をプレイ済みだとより深く理解できます。

## 学べる概念

### 境界づけられたコンテキストとデータ

- **コンテキスト境界でのデータ分離**: 各コンテキストが独自のデータモデルを持つ原則
- **データ所有権**: どのコンテキストがどのデータの「真実の源泉」か
- **コンテキストマッピングパターン**: 共有カーネル、Customer-Supplier、ACLなどのデータ連携パターン

### データ統合パターン

- **データベース統合 vs API統合**: 共有DBの問題と代替手段
- **イベント駆動データ同期**: イベントソーシングとCQRSによるデータ分散
- **Saga パターン**: 分散トランザクションの代替としての補償トランザクション

### データメッシュ

Zhamak Dehghaniが提唱する、データのドメイン指向分散アーキテクチャ：

- **ドメインオーナーシップ**: データをドメインチームが所有
- **Data as a Product**: データを製品として扱う
- **セルフサービス・インフラ**: データ基盤のプラットフォーム化
- **連邦計算ガバナンス**: 分散しつつも標準を維持

### 結合度と凝集度

Vlad Khnovovの「結合バランス」フレームワークに基づく品質評価：

- **統合強度**: コンポーネント間の依存の強さ
- **距離**: 変更が伝播する範囲
- **安定性**: 変更頻度と影響範囲のバランス

## 想定される学習成果

- 共有データベースの問題点と脱却戦略を理解
- コンテキスト境界に沿ったデータ分離の設計能力
- データ統合パターンの使い分け判断力
- 結合度を意識した品質の高いデータ設計

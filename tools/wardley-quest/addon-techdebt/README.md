# Technical Debt Quest

[Strategic Evolution Quest](../) のアドオンシナリオ

技術的負債の可視化・優先順位付け・返済計画を学ぶRPG。「走りながら負債を返す」現実の困難さを体験し、持続可能な負債管理戦略を身につけます。

## 前提

**単体でもプレイ可能です。** [Strategic Evolution Quest](../) をプレイ済みだとより深く理解できます。

## 学べる概念

### 技術的負債の本質

Ward Cunningham が提唱した概念を、金融の負債メタファーで理解します。

- **負債の性質**: 借りた時は楽（開発が速い）、利子がつく（将来の変更コスト増）、複利で増える
- **金融との違い**: 残高が見えない、利率が分からない、返済期限がない
- **負債の種類**: 意図的な負債（Strategic Debt）と非意図的な負債（Accidental Debt）

### Martin Fowler の4象限

技術的負債を「意図的/非意図的」×「無謀/慎重」の4象限で分類：

- **危険な負債**: 「設計する時間なんてない」（無謀×意図的）
- **戦略的な負債**: 「今はこれで出荷しよう」（慎重×意図的）
- **無知による負債**: 「レイヤリングって何？」（無謀×非意図的）
- **学習による負債**: 「あぁ、こうすべきだった」（慎重×非意図的）

### 負債の可視化と測定

- **可視化度**: 負債がどれだけ組織に認識されているか
- **利子率**: 負債による開発速度低下の度合い
- **コード健全性**: コードベース全体の健全度指標
- **負債の棚卸し**: 定期的な負債の洗い出しと分類

### 返済戦略パターン

- **ボーイスカウトルール**: 触ったコードは少し良くして離れる
- **Strangler Fig**: 段階的にレガシーを絞め殺す
- **負債返済スプリント**: 定期的に負債返済に集中する期間を設ける
- **リファクタリング vs リライト**: 状況に応じた適切な判断

## 想定される学習成果

- 技術的負債を「悪」ではなく「管理すべきリソース」として捉える視点
- 負債の可視化・優先順位付けの実践的な手法
- ビジネス要求と返済のバランスを取る判断力
- 負債が増えにくい文化を育てるためのアプローチ

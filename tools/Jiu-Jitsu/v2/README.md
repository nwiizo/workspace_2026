# 柔術道場 — 動かして、作用を考える

骨格や身体の条件を動かし、その変化を柔術の攻防へつなげるブラウザゲームです。
入口は、点のドラッグとスライダーで操作する「動きの道場」。正答を選ぶ操作や制限時間はありません。

## コンセプト

「技名を知っている」よりも、「どう動かすと、何が変わるか」を考えられることを目指します。
骨は支柱やテコになり、関節が動く方向を作り、筋肉が力を出して動きや姿勢を保つ。
これらを重ねて眺め、条件を一つ変え、前後を比べます。

### 動きの道場

| 動かすもの | 遊びの目標 | 柔術とのつながり |
|---|---|---|
| 前腕の傾き、力を受ける位置 | 下向きの力の線を肘の近くへ寄せる | フレームの向き、腕を遠くへ出したときの作用 |
| 左右の支え、重心の投影 | 重心を支持範囲の中へ戻す | 上でのバランス、相手の手足の支えを止める意味 |
| 股関節と膝 | 膝と足首を同時に青い枠へ収める | 脚を折りたたむ動きと、膝の位置を戻す動きの違い |

丸い点をドラッグすると、その場で骨格と計算結果が変わります。スライダーはタッチと矢印キーでも操作できます。
骨格・筋肉の位置・重ね合わせを切り替え、「今の状態を比較元にする」で変化を見比べられます。
複数の動かし方で目標へ届き、達成後も自由に動かせます。発見の記録はブラウザに残ります。

### ポジション練習

体の実験から、青を自分に固定した5課題へ進めます。

1. **サイドの下** — 前腕で支え、腰を引き、膝を戻す。腕を伸ばして押すと、作った空間を失う場面もある。
2. **マウントの下** — 低い位置では同側の手足を止めて返す。高い位置では膝肘の空間を探す。
3. **ガード内の上** — 土台・姿勢・両肘を保つ。相手が腰の角度を作ったら向き直る。
4. **サイドの上** — 膝の壁がなければ進み、膝を戻されたら抑え直す。
5. **バックを取られたところ** — 首への腕と持ち替えを追う。防御できない形ではタップで止める。

この補助モードは、一手ごとのボタン操作です。各課題に2種類の相手の反応があり、現在の支え・隙間・脚の位置で進める操作が変わります。
操作後に「前→後」と相手の反応を確認し、手動で次へ進みます。数字キー1〜4、結果の確認はEnter、タップはT。
通常のタップは記録を減点せず中断します。絞めが組まれた課題では、タップそのものが目標の達成です。

「ヒントを見ながら練習」と任意の確認練習があります。確認は相手の反応を交互に変え、ヒントなし・やり直しなしの完了を記録します。
ヒントや体の実験へのリンクを使った確認は、復習対象にします。確認済みは実技の習得や帯の判定ではありません。
実験へ移動して戻っても、進行中のポジション練習は保持されます。

人形は二人を一組で配置し、膝・足など床につく場所を丸印で示します。胸郭・骨盤・手足の厚みを見る「身体」と、骨の位置とつながりを見る「骨格」を切り替えられます。「相手を透かす」で隠れた自分の腕も観察できます。
「接地を横から」「真上」で視点を変え、一手の結果では「一手の前／一手の後」を同じ視点で比較できます。比較中は人形・見出し・状態説明が一緒に切り替わり、練習の進行や記録は戻りません。

### 資料と記録

- **関節の資料** — 「動きの道場」の末尾から開く7関節の3D資料。円弧と角度は表示用です。安全域の色分けや、限界を待ってタップする演出はありません。
- **稽古記録** — 動きの発見、基礎課題の確認、従来の応用ロールの記録。基礎確認はLeitner式で復習時期を表示します。
- **応用ロール** — 9局面・25初動を使う選択式モード。ポジション練習と同じ人形で身体／骨格、相手の透過、接点、視点を切り替え、回答後は「一手の前／一手の後」を比較できます。攻撃では赤、防御では青が自分で、凡例と透過する相手も切り替わります。画面やブラウザタブを離れた間、判断時間は進みません。
- **心得** — ポジション・用語・従来の参考文献。

## モデルが扱う範囲

- **テコ**：固定した肘、一定の下向きの外力、前腕の傾きから水平距離を計算します。同じ力なら回転作用はその距離に比例します。筋力や接触圧を推定しません。
- **支え**：左右の支持範囲と、入力した重心投影の位置を比べます。重心を姿勢から推定せず、摩擦・相手の力・前後方向・手をつく反応は計算しません。
- **脚**：骨盤を固定した平面内の2本リンクです。大腿とすねを各40cmとする例で、骨の長さを保ちながら関節を動かします。相手や床との衝突はありません。
- **筋肉の図**：位置と役割の模式図です。筋活動量・付着部の精密形状・組織の変形を再現しません。
- **ポジションの3D**：胸郭と骨盤、固定長の手足で作る模式図です。膝の厚みを含めて接地位置を決め、手足の目標位置と曲げる側から肘・膝を計算します。届かない目標では骨を伸ばさず、到達範囲に収めます。状態間は静止画を切り替え、中間の動作・衝突応答・摩擦・組織の変形・筋力は計算しません。骨格も骨の精密形状を再現したものではありません。

青い目標枠や数値はゲームの条件です。人体の安全限界、実際の技の成否、実技の上達を測定するものではありません。
実技は指導者と行い、タップは痛みや苦しさを待たずに伝えてください。

## 実装と検証

「ルート作成」では二人の人形の手・足・腰をドラッグし、姿勢を順番に登録できます。肘・膝の点は曲げる方向の指定です。座標入力と胴体の回転ボタンでも操作でき、身体／骨格・透過・視点を切り替えられます。登録した姿勢は名前・秒数・順番を変更でき、再生とスライダーで途中の動きを確認できます。プレビュー後は「姿勢の編集へ戻る」か、登録済みの姿勢を選びます。

到達距離・屈曲の表示範囲・床や自分／相手の身体内部への貫通を検査し、問題のある姿勢の登録を止めます。途中は24分割の検査と再生中の検査を併用し、干渉や肘・膝の急な切り替わりがあれば停止します。体幹は剛体、身体内部は楕円体、四肢は代表点で近似しています。手足同士の接触や筋力・摩擦・肩／股関節の回旋の可否を判定する完全な人体シミュレーションではありません。支持がない配置や極端な向きは確認事項として表示し、「指摘なし」を実技の可否・安全判定にしません。関節の動きの整理は [OpenStax](https://openstax.org/books/anatomy-and-physiology-2e/pages/9-5-types-of-body-movements) を参照しています。

2026年9月7日に調査し、パス後の上の支配、バックでの手の対応、ガードでの腰角度の3例を登録しています。[IBJJFの2026年世界選手権総括](https://ibjjf.com/news/2026-world-championship-black-belt-recap) にあるパス連携・バックへの攻撃・アームドラッグから、既存モデルで観察できる部分を練習例にしたものです。選手の試合動作のトレースや、技の流行を数量的に証明するものではありません。[ADCCの9月6日付発表](https://adcombat.com/official-competitor-list-for-the-adcc-world-championship-2026-updated/) も確認し、9月12〜13日の大会結果は未開催のため扱っていません。自動巡回による継続更新は行いません。

登録済みの3例はアプリに組み込み、いつでも開けます。自作ルートは1件を `jiu-jitsu-dojo-v2/route` に保存します。既存の稽古記録とは別のキーです。形式は `version: 1` / `name` / `frames`。各フレームは `label` / `seconds` / `blue` / `red`、各身体は `pelvis`（XYZ・m）/ `rotation`（XYZW quaternion）/ `arms` / `legs`。腕・脚は左右の順で、それぞれ `[先端のXYZ, 曲げる方向のXYZ]` を保存し、骨の位置・指摘は再計算します。登録は40姿勢まで、秒数は0.5〜10秒。未対応の版や不正な座標は元データを消さずに拒否し、保存できない場合は表示します。未登録の編集には画面離脱時の確認が入り、既存の自作ルートを登録例で置き換える操作にも確認があります。

| ファイル | 役割 |
|---|---|
| `src/anatomy/mechanics.ts` | テコ・支持範囲・脚の平面運動、操作結果による達成判定 |
| `src/labs/bodyLab.ts` | ドラッグ、スライダー、骨格と筋肉の図、前後比較 |
| `src/content/practice.ts` | 5課題の状態・操作・相手の反応・到達点 |
| `src/engine/practice.ts` | 操作可能性、失敗・タップ、振り返り、重複記録の防止 |
| `src/ui/practiceTab.ts` | 3Dの観察、操作、結果、体の実験との往復 |
| `src/render/practicePose.ts` | 課題と状態ごとの二人の配置、手足の目標、接点 |
| `src/render/mannequin.ts` | 固定長の二節の計算、胸郭・骨盤・四肢、骨格と身体の表示 |
| `src/render/rollPose.ts` | 応用ロールの開始・初動・回答後の二人の配置。腕十字・三角・開いたガード |
| `src/render/bodyScene.ts` | 練習と応用ロール共通の接地の丸印、観察用カメラ、透過表示。操作時だけ描画 |
| `src/ui/routeTab.ts` / `src/engine/route.ts` | 人形のドラッグ、姿勢の編集・連結、到達距離・干渉・途中の動きの検査 |
| `src/content/routes.ts` / `src/engine/routeStorage.ts` | 調査出典付きの登録例と、自作ルートの保存・読込検証 |
| `src/engine/storage.ts` | 既存の保存形式で記録。読み取れない項目のみ除外 |

テストは、一連の操作・全分岐の到達性・相手反応別の手順・失敗による後退・タップ・連打・ヒント使用・復習・保存を確認します。
力学は手計算できる入力と結果で検証し、関節の動きでは骨の長さが変わらないことも確認します。
従来のコンテンツ、ポーズ、スクランブルエンジンのテストも継続しています。

人形は練習の33場面と応用ロールの82場面で支持位置・骨長・メッシュ頂点の床への貫通・相手の胸郭／骨盤の中心への四肢の侵入を検査します。応用ロールでは頭の内部も検査します。内部の楕円体と四肢の代表点による検査なので、あらゆる表面接触や自己接触を保証する衝突判定ではありません。低い／高いマウントの違い、ガードでの膝の囲い、首の付け根へ手が届くこと、腕十字での手首と肘の位置も検査します。

表示の検証は開発サーバーの `/_practice-audit.html` から全状態を選べます。練習は `?lesson=mount-base&node=high&view=side`、応用ロールは `?roll=attack-triangle-guard&stage=1`。stage は0が開始、1が基本の攻防、その後は初動、回答後の順です。`view=top` / `view=diagonal`、`&bones` / `&fade` も使用できます。数値だけで済ませず、胸・腰・膝・足の重なりを横・上・斜めから確認してください。関節資料に残る角度リグの検証は `/_audit.html` です。

ブラウザ確認には導入済みの `agent-browser` を使用できます。ドラッグで3課題を達成し、記録の再読み込み、ポジション5課題、資料との往復、スマートフォン幅を確認します。
ブラウザでの学習が実際のBJJの上達につながるかは、指導者・学習者による評価が必要です。

## 参考資料

基礎的な解剖・力学の説明は以下を参照しています。BJJの課題への落とし込みと目標枠の設計は、このゲームでの設計判断です。

- [OpenStax — Forces and Torques in Muscles and Joints](https://openstax.org/books/college-physics-2e/pages/9-6-forces-and-torques-in-muscles-and-joints)：力の向きと作用点の距離。

- [OpenStax — Interactions of Skeletal Muscles](https://openstax.org/books/anatomy-and-physiology-2e/pages/11-1-interactions-of-skeletal-muscles-their-fascicle-arrangement-and-their-lever-systems)：骨・関節・筋肉とテコの関係。
- [OpenStax — Nervous System Control of Muscle Tension](https://openstax.org/books/anatomy-and-physiology-2e/pages/10-4-nervous-system-control-of-muscle-tension)：姿勢を保つときの筋張力。

- [Stephan Kesting — The Frame and Hip Escape](https://www.grapplearts.com/powerful-guard-pass-defense-used-carlson-gracie/)：フレームと腰の移動。

# 柔術道場 v2 — Grappling Structure Dojo

赤と青の 3D 人体で柔術の**状況判断**と**人間の関節・構造**を学ぶブラウザ教育ツール。
v1 (親ディレクトリ) のコンセプトを引き継ぎ、技術選定をやり直した全面再構築版です。

## v2 の設計思想

1. **解剖モデルが第一級のデータ** — 関節タイプ (蝶番/球/車軸/顆状)・軸ごとの運動名・
   表示リグ可動域・解剖学的参考可動域・制限構造 (靭帯/骨)・破綻モード・対応サブミッションを
   `src/anatomy/joints.ts` に型付きで持つ。この 1 つのモデルが
   (a) 3D レンダリングの関節 clamp、(b) 全ポーズの検証テスト、(c) 関節ラボの教育コンテンツ、
   の 3 役を駆動する。「なぜその技でタップするのか」を構造から説明できる。
2. **スクランブル式ロール (台本なし)** — 固定のシナリオ列を持たない。
   ポジショングラフ (局面ノード + 選択肢の next 辺) を、回答結果 × 引き継ぎ状態 ×
   フォーカス × 弱点優先度の重みで動的に歩く。同じ開始局面でも相手の初動と展開が毎回変わり、
   ミスしても相手の追撃から不利な局面へロールが続く。
3. **間隔反復で「適切に学べる」** — (局面 × 相手初動) を学習項目とした Leitner 式 SRS。
   忘れかけた頃に弱い項目が再出題され、稽古記録タブで習熟が見える。localStorage に永続化。
4. **教育原則は v1 を継承** — ポジション階層 / position before submission /
   「タップ=学び・安全装置」。研究の裏付け (Spanias 2022, Scoggin 2014 ほか) は
   心得タブに収録。position before submission が上半身サブミッション限定で統計的に
   成立する点 (下半身関節技には当てはまらない) を歪めない。

## v1 からの技術選定の変更

| 領域 | v1 | v2 | 理由 |
|------|----|----|------|
| 言語 | Vanilla JS + 手書き検証スクリプト×2 | TypeScript strict + Vitest | ポーズ参照・next 参照・状態フラグの整合が型で落ちる。残りの不変条件はテストに移植 |
| 3D | Three.js CDN・服飾ディテール重視 | Three.js (npm)・骨格/関節を主役に描画 | 教育対象が「関節と構造」なので、関節マーカーを常時表示し可動域を可視化する方が学習に効く |
| ポーズ検証 | 幾何チェック群 + 監査 HTML + スクショ反復 | 解剖モデルの可動域テスト (全ポーズ×全関節) | 検証インフラを解剖モデルに一本化 |
| ロール進行 | 事前生成スロット列 + 差し替え | スクランブル式グラフ歩行 | 台本を排し、実ロール的な創発性と反復可能性を両立 |
| 学習管理 | セッション内スコア・帯 | Leitner SRS + localStorage + 稽古記録 | 間隔をあけた検索練習 (spacing/retrieval) が定着に効く |
| ビルド | なし (CDN) | Vite | 型検査・テスト・依存管理のため。成果物は静的サイト |

v1 のミッション/戦術制約/流れメーター/相手スタイルは v2 では未移植 (学習コアを優先)。
必要になったら next 重みへの乗数として同じ場所に足せる。

## 動かし方

```sh
npm install
npm run dev      # 開発サーバー
npm run check    # 型検査
npm run test     # Vitest (コンテンツ不変条件 / ポーズ可動域 / エンジン / SRS)
npm run build    # 型検査 + 静的ビルド (dist/)
```

## 画面

- **道場** — スクランブル式ロール。局面 → 相手の初動 (attack) → 数字キー 1〜4 で判断 →
  フィードバック (読めた線/見落とした線・相手の反応/追撃・原則・危険な関節) → Enter で次局面。
  入門=時間制限なし / 実戦=判断制限時間 + 時間切れは悪手扱い。終了時にロールレビュー。
- **関節ラボ** — 単体骨格で関節を選び、軸スライダーで動かして可動域を体感する。
  安全域 (解剖学的参考可動域) と限界域を 3D アークと色で表示し、
  その関節を攻めるサブミッションと「なぜタップするか」(制限構造・破綻モード) を解説。
- **稽古記録** — (局面 × 相手初動) ごとの習熟 box、復習どき、帯 (白→青→紫→茶→黒)。
- **心得** — ポジション階層・原則・用語・研究の裏付け。

## ファイル責務

| パス | 役割 |
|------|------|
| `src/anatomy/` | 関節の解剖モデル (型 + データ + clamp + 検証) — 本ツールの核 |
| `src/render/` | rig(骨格トポロジー) / poses(関節角ポーズ, v1 から移植) / fighter(骨格主役レンダラ + floor probe) / scene(畳・ライト・カメラ) |
| `src/content/` | 教育コンテンツ。9 局面 (防御4 + 攻撃5) × 相手初動 × 選択肢。requiresAction/State で初動・状態別に正解が変わる |
| `src/engine/` | roll(スクランブルエンジン) / srs(Leitner) / storage(永続化) / rng(シード可能乱数) |
| `src/labs/` | 関節ラボ |
| `src/ui/` | タブ・ロール画面・ダッシュボード (素の DOM) |
| `tests/` | コンテンツ不変条件 / ポーズ可動域 / エンジン決定性 / SRS |

## 局面の追加

1. `src/content/scenarios/` に 1 ファイル追加し `scenarios.ts` に登録 (ScenarioId 型にも追加)
2. 新ポーズが要る場合は `src/render/poses.ts` に座標規約どおり追加 (PoseName 型が参照整合を保証)
3. `npm run test` — 可動域・正解一意性・next 参照のテストが落ちなければ完成

## 免責

本ツールは概念理解のための教育用デモです。関節技・絞め技は危険を伴います。
実技は必ず有資格指導者の監督下・適切なマット環境で、**早めのタップ**を徹底してください。

## 既知の課題 (v2 は Web リファレンス実装として凍結)

ネイティブ版 (Rust + Bevy + Rapier) への移行に伴い、v2 は参照実装として凍結。未修正のレビュー指摘:

- 実戦モードのタイマーがタブ切替中も走り続け、裏で時間切れ→SRS 降格が起きる (P1)
- 非アクティブタブの WebGL レンダループが停止しない (P2)
- localStorage の SrsItem 単位の形状検証なし (P3)
- gating テストは状態フラグ単体のみで 2 フラグ同時の組合せ未検証 (P3)

# 柔術道場 (ネイティブ版) — Grappling Structure Dojo

人間の**関節と構造**を物理で理解しながら柔術の状況判断を学ぶネイティブアプリ。
Web 版 (`../v2`) の「関節を手打ち角度で並べる」限界を越えるための作り直し。

## なぜ Web をやめてネイティブにしたか

目的は「関節と構造を*正確に*理解する」こと。Web 版 (Three.js プリミティブ + 手打ちオイラー角) の限界:

1. **関節が見た目でしかない** — 可動域は表示 clamp。実際の関節軸・ROM を*シミュレートしていない*。
2. **物理拘束がない** — 寝技の噛み合いを座標の手調整で作る (バグの温床だった)。
3. **ブラウザの天井** — スキンメッシュ + 物理 + 複数体のリアルタイムが重い。

## 技術選定

| 層 | 採用 | 理由 |
|----|------|------|
| 言語 | **Rust** | ワークスペースの資産・型安全・ネイティブ性能。関節モデルを純データとして持てる |
| エンジン | **Bevy 0.16** (ECS) | Rust ネイティブ、glTF スキンメッシュ、データ駆動で局面/UI を組みやすい |
| 物理 | **Avian 0.5** | ECS 統合の物理。`RevoluteJoint`/`SphericalJoint` のリミットが解剖モデルに直結 |

比較検討: **Godot 4 (+godot-rust)** は反復が速いがコアが Rust でない。**MuJoCo** は筋骨格の忠実度が最高だが学習 UI の作り込み工数が大きい。Rust ネイティブ + 物理関節の目的適合で Bevy+Avian を採用。

## 設計の背骨: 解剖モデル → 物理ジョイント

`anatomy` クレートの関節分類が、そのまま物理ジョイントの種類とリミットになる:

| 解剖 (`JointKind`) | 例 | Avian ジョイント |
|---|---|---|
| `Hinge` | 肘・膝・足首 | `RevoluteJoint` + `angle_limit` (骨性ストップ) |
| `BallSocket` | 肩・股 | `SphericalJoint` + `swing_limit` / `twist_limit` |
| `Pivot` / `Condyloid` | 首・手首 | `SphericalJoint` で近似 |

これで **「腕十字 = 肘 revolute joint を伸展下端 0° を超えて伸ばす技」** を物理で表現でき、
タップ = 関節がリミットを超えた瞬間、として扱える。Web 版で最も弱かった「なぜ壊れるか」が
*シミュレーション*として説明可能になる。

## クレート構成

| クレート | 役割 |
|----|------|
| `crates/anatomy` | 関節の解剖モデル (純 Rust・依存なし)。7 関節 × 軸可動域 × 物理ジョイント記述 × 教育コンテンツ。`cargo test -p anatomy` が高速に通る核 |
| `crates/dojo` | Bevy + Avian アプリ。`rig.rs` が解剖モデルを Avian ジョイントへ変換し articulated 人体を組む |

## 動かし方

```sh
cargo test -p anatomy   # 核のテスト (高速・GUI 不要)
cargo run -p dojo        # アプリ起動 (初回は Bevy のビルドに数分)
cargo check              # 全体の型検査
```

## 品質目標とゲーム機構 (北極星 = EA Sports UFC 6)

**目標の再定義**: フォトリアルな見た目は個人 + Bevy では非現実的 (AAA は数百人年規模)。
そこで **UFC の"機構と手触り"を北極星にし、見た目はスタイライズ、関節は物理で本物** とする。
UFC がアニメで抽象化する関節破壊を、本ツールは物理 (Avian の関節リミット) で*本物*にでき、
これが教育ツールとしての勝ち筋。

**UFC 系グラウンド機構 (調査: UFC 5 Seamless Submission → UFC 6 ハイブリッド)**:
- ミニゲーム廃止。サブミッションはグラウンドの流れの延長。
- ポジション基盤 (マウント/バック/サイド/ガード/ノースサウス) を遷移。相手は遷移を拒否 (stuff) でき、
  拒否は攻め側のスタミナを大きく削る — スタミナ管理と読み合いが核。
- キャラクターモデル上の視覚的キューで入力方向を提示。
- → 本ツールの v2 スクランブルエンジン (ポジショングラフ + 重み付き遷移 + readCues) と同型。
  不足は「リアルタイム遷移/拒否/スタミナ + 体のキュー」。

**UFC 6 の技術要件と本ツールでの扱い**:
| 技術 | 本ツール |
|------|---------|
| マーカーレス mocap / 1000+ アニメ | 採らない (スタジオ規模)。少数の手付けポーズ + IK/補間で代替 |
| Frostbite Driven Ragdoll | **採用** — Avian の関節モーター + リミットで実現 |
| Sapien (選手ごとの解剖写像) | 簡易版 = `anatomy` クレート |
| フォトリアル/布/実写ライクネス | 採らない |

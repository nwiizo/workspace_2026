# 柔術ディフェンス道場 — 設計・研究・ロードマップ

赤(攻)と青(守)の3D人体で柔術を学ぶブラウザ教育ゲームの、設計方針・調査結果・タスク全件をまとめた開発ドキュメント。
要件定義・技術選定は [REQUIREMENTS.md](REQUIREMENTS.md) を正とする。アプリの使い方は [../README.md](../README.md)、運用制約は [../CLAUDE.md](../CLAUDE.md) を参照。

## 1. コンセプト

- 技のコレクションではなく **原則** を学ぶ。柔術指導の背骨である **ポジション階層** と **position before submission**、安全文化（**タップは負けでなく学び・安全装置**）を中心に据える。
- 「状況 → 判断」形式は現代の指導法（Constraints-Led / 生態学的ダイナミクス）に沿う。
- ビルド不要。Three.js 0.169 を CDN importmap で読込。静的サーバー必須（`file://` 不可）。

### 座標規約（poses.js / poseSpecs.js）

立位は `root.y=0.92`・顔はローカル +Z・脊柱は +Y。腕脚はローカル -Y へ伸びる。開始姿勢は赤青が互いの root 方向を向く。
寝技の仰向け/うつ伏せは、頭方向を含む helper 名で明示する。詳細な採用規約と禁止事項は [REQUIREMENTS.md](REQUIREMENTS.md#4-3-座標規約) に従う。
`poses.js` は関節角、`poseSpecs.js` は重心・支持基底・接触点・力の方向を担当する。新規 pose は必ず両方に追加し、角度だけの未仕様ポーズを作らない。`scripts/validate-data.mjs` は首/肩/肘/股関節/膝/足首の関節角レンジ、root 座標の高さレンジ、scenario ペアの水平距離、上位/下位または捕獲関係の高さ、role 別の向き関係、相手に荷重する pose の支持中心と力ベクトル、`_audit` の支持中心起点 force marker と荷重線も検証し、目視だけに依存しない。
人体モデルの可動域・膝ヒンジ規約・IK/glTF への移行基準は [HUMAN_BODY_MODEL.md](HUMAN_BODY_MODEL.md) を正とする。膝は `shin*.x >= 0` の屈曲だけを許し、脚の開きや三角の角度は股関節と root で作る。`anatomy.js` の制約を `validate-data` と `fighter.js` が共有し、レンダリング時にも関節角を clamp する。床付近の pose には floor probe による root 高さ補正を入れ、マット抜け/浮きを軽減する。
ポジション分類は [POSITION_TAXONOMY.md](POSITION_TAXONOMY.md) と `positionCatalog.js` を正とする。全BJJの主要ファミリーは分類するが、ゲームに出せるのは `implemented: true` の family に属し、かつ `ALLOWED_ROLE_PAIR_RULES` で明示された赤/青 role ペアだけ。

### 既知の問題（codex独立レビュー、現在の扱い）

- **P1**: `scripts/validate-data.mjs` で未定義ポーズID、重複ID、role、pose spec、全BJJポジション分類、実装済み family、明示許可された赤/青 role ペア、関節角レンジ、root 座標の高さレンジ、scenario ペアの水平距離/高さ/向き/支持中心/力ベクトル、`_audit` の身体制約マーカー、gi/nogi/state/action 表示別正解数、`stateBias` / action 条件参照、action-gated choice 数と局面数、モード分岐有無、`timeLimitSec`、`pressure`、相手初動数と3件以上の初動を持つ局面数、正解 choice の `reaction`、不正解 choice の `consequence`、`next` 参照、重み付き `next` 形式を検証。`scripts/validate-game-logic.mjs` でラン生成、next 重複回避、rollState による next/timeout 重み補正、防御/攻撃をまたぐ初動別正解分岐を検証。ガード腕十字の赤/青ポーズ逆転は修正済み。
- **P2**: 同一局面のリプレイ再回答でスコア/連続正解/流れが二重反映されないよう、局面 index の初回解決状態で抑止。
- **P3/P4**: `renderBadge` / 原則表示は `<b>` のみ許可する簡易サニタイズに変更。roleタグはシナリオrole基準に修正。
- **残課題**: 3Dポーズは方向・上下関係・支持中心・相手へ向く力ベクトルの最低条件を `validate-data` で検証する。`poseSpecs.js` に役割・支持基底・接触点・力の方向を定義し、`_audit` に重心投影/支持エリア/支持中心起点の力ベクトル/相手への荷重線/接触点ラベルを追加した。サイドコントロールは胸圧と下側フレーム、マウントは骨盤位置と前傾、クローズドガードは足首ロック寄り、ガード腕十字・三角は捕まる側の姿勢崩しと脚の捕獲感を再調整済み。ただし腕十字の肘支点、三角の膝裏/足首ロック、細かい接触はプリミティブ骨格ではまだ記号的。各 scenario に `readCues` を持たせ、3Dだけでは読み落としやすい首・肘・腰・フレームの判断対象を短いチップで補助する。
- **人体モデル方針**: 現MVPは角度制約付きプリミティブで継続し、膝はヒンジ、肘もヒンジ寄り、肩/股関節は多軸だが安全側の可動域に制限する。レンダリング時にも関節角 clamp と floor probe grounding を行う。手足の接触が角度手打ちで繰り返し破綻する場合は、次段階で `SkinnedMesh` + 2-bone/CCD IK、必要なら glTF 人体リグへ移行する。
- **設計推奨**: 初期の状態フラグは `rollState`、state 条件付き選択肢、`stateBias` による次局面重み補正で実装済み。次は SCENARIOS を ID付きマップ化し、現在の choice `reaction` / `consequence` / 重み付き `next` 候補をより明示的なシナリオグラフへ拡張する。SCENARIO に `steps[]` と `preferredMode` を追加。`Fighter.setMode` を Dojo 経由で呼ぶ。これらが #2/#3/#4/#7 の共通前提。

## 4. 研究サマリ（英語文献・最新研究）

詳細・全出典は `docs/research-grappling.md` / `docs/research-strength-anatomy.md`。エビデンス強度ラベル付き。

### 教育・原則の裏付け

- **「position before submission」は上半身サブミッション限定で統計的に成立**（Spanias et al. 2022：位置の優位は上半身の極めと相関 r=0.50, p<0.05。一方ヒールフック等の下半身関節技は位置支配なしでも決まる）。→ 本ゲームの上半身中心の攻防は原則が効く領域。「正解が変わる」機構はこの知見＋ルールセット別合法性で二重に裏付け。
- **腕十字は最多の受傷機転**（Scoggin et al. 2014：整形外科的傷害の38.9%が肘、肘傷害14例中10例が腕十字）。傷害率約9.2/1000 exposure で MMA・柔道より大幅に低い。早期タップが第一の傷害予防。
- **教育効果**：学校でのBJJプログラムRCTで児童の認知的自己制御・教室行動の改善。
- **指導法**：Constraints-Led / 生態学的ダイナミクスは状況で解を発見させる学習を支持（直接のBJJ専用研究は限られMMA研究等からの援用を含む点を明記）。

### 連鎖（パズル/フローの素材）

- サブミッションチェーン：腕十字↔三角↔オモプラッタ、キムラトラップ、フロントヘッドロック（ギロチン↔ダース↔アナコンダ）。相手の反応が次手を開く `STATE | 反応 → 技` を約45件抽出（Appendix A）。
- エスケープ連鎖：マウント/サイド/バック/ニーオンベリー/N-S の再コントロール反応とタイミング（膝が中心線を越える前に動く）。
- レッグロック：アシガラミ階層（インサイド/サドル=ハニーホール/50-50/アウトサイド）、control-before-submission、防御（踵を隠す・ハンドファイト・トルクと同方向に回る）。

### 相手アーキタイプ（6類型）

プレッシャーパサー／レッグロッカー（足関おじさん）／ガードプレイヤー／レスラー／柔道家／絞めハンター。各々の典型攻め筋と対策ゲームプラン。
MVP ではランダム／プレッシャーパサー／絞めハンター／ガードプレイヤーを UI で選べるロールスタイルとして `game.js` に持たせ、出題順、正解後の `next` 優先、実戦時間切れ時の悪手選択、実戦モードの相手意図へ反映する。ガードプレイヤーは `closed-guard-posture` / 腕十字 / 三角を優先する。本格実装では類型別シナリオ、`next` 重み、見た目差へ広げる。

### 筋トレ・解剖（#10素材）

- 握力持久が最もBJJ特異的。等尺性・後鎖・股関節・抗回旋体幹・頸部・混合持久力。
- 動作→主働筋→推奨種目の対応表（ブリッジ/フレーム/海老/ガードリテンション/グリップ/テイクダウン/絞め）をリグ領域（首/胸/上腕/前腕/手/腹/腰/股/腿/脛）にマップ済み。
- **誠実な留保**：頸部強化は傷害減少のエビデンスなし、減量は美化しない、表現は「Xで使う筋肉を鍛える/上級者と関連」に留め「上達/傷害予防」と断定しない。

## 6. 実行・検証

```sh
cd Jiu-Jitsu && python3 -m http.server 8080 --bind 127.0.0.1   # → http://localhost:8080
for f in js/*.js; do node --check "$f"; done                    # 構文
node scripts/validate-data.mjs                                  # データ整合
node scripts/validate-game-logic.mjs                            # 状態機械
```

3D描画の確認はヘッドレスChrome（`--headless=new --enable-unsafe-swiftshader --virtual-time-budget=1500 --screenshot=...`）でスクショし目視。`virtual-time-budget` は短め（無限rAFで固まるため）。`timeout` は macOS 非搭載（`gtimeout`）。`_audit.html?q=guard` のように `q` パラメータで対象ラベルを絞れる。既定では重心投影/支持エリア/支持中心起点の力矢印/荷重線を表示し、見た目だけを確認する場合は `markers=off` を付ける。

## 7. 免責

教育用デモ。関節技・絞め技は危険を伴う。実技は有資格指導者の監督下・適切なマット環境で、相手の安全に配慮し **早めのタップ** を徹底して行うこと。

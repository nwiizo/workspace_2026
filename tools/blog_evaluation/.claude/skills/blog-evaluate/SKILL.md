# ブログ記事総合評価 v2.3

指定されたブログ記事を7つの観点から評価し、建設的で実践的なフィードバックを提供する。

## 実行手順

### 1. 引数の解釈

$ARGUMENTS をファイルパスとして解釈する。

- ファイルパスが指定された場合: そのファイルを読み込む
- 指定がない場合: ユーザーにファイルパスを確認する

### 2. 評価基準の読み込み

詳細な評価基準を読み込む:

```
Read: ${CLAUDE_SKILL_DIR}/../../../evaluation-prompt.md
```

### 3. 記事の前提確認

記事を読む前に以下を把握する:
- ターゲット読者層
- 記事の目的（学習記録/チュートリアル/考察/ポストモーテム等）
- 著者の経験レベル
- 企業名・組織名が紐づくか（紐づく場合は1段階厳しく評価）

### 4. 7観点で評価

| # | 観点 | スコア | 備考 |
|---|------|--------|------|
| 1 | 防御力 | 0.0-5.0 | 批判に耐えうるか |
| 2 | 思考整理力 | 0.0-5.0 | 論理的に構造化されているか |
| 3 | 実践応用性 | 0.0-5.0 | 読者が行動に移せるか |
| 4 | 構成と読みやすさ | 0.0-5.0 | 読者の理解を促進するか |
| 5 | コミュニケーション力 | 0.0-5.0 | 人間味があるか |
| 6 | 炎上リスク | 0.0-5.0 | 社会的配慮（高いほど安全） |
| 7 | 人間らしさ | 0.0-5.0 | AIっぽくないか |

### 5. スコアの厳格性

- **5.0**: 例外的（全体の5%未満）。プロ編集者が見ても非の打ち所がない
- **4.0**: 商業メディアレベル（15%程度）
- **3.0**: 標準的な技術ブログ（50%程度）
- **2.0以下**: 改善が必要
- 迷ったら低い方を付ける

### 6. 出力形式

`evaluation-prompt.md` の「評価レポート形式」セクションに従い、以下を含むMarkdownレポートを出力:

1. **評価サマリー** - 総合評価（5項目平均）、炎上リスク、人間らしさ、プログレスバー付き項目別スコア
2. **各項目の詳細評価** - 良い点・改善点・改善案を具体例とともに
3. **炎上リスク分析** - リスク要因、チェックリスト結果、リライト例
4. **人間らしさ分析** - 人間的要素、機械的特徴、向上提案
5. **総評** - 2-3文で核心的価値と印象
6. **優先改善提案 TOP3** - 現状・改善案・期待効果
7. **リライト例** - 炎上リスク軽減・人間らしさ向上のBefore/After
8. **記事の強み** - TOP3

## 改善提案の優先順位

1. 炎上リスクの排除（最優先）
2. 即効性の高い改善（タイトル、導入部、見出し）
3. 価値を大きく向上させる改善（具体例追加、視覚要素）
4. 長期的な成長につながる改善（文体の個性化）

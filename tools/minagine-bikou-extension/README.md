# Minagine 備考一括入力 Chrome拡張

`https://work.minagine.net/work/wrktimemngmntshtself/sht` の勤怠表で、各行の備考欄に「自己啓発・研鑽」を一括入力するChrome拡張機能です。

## インストール

1. Chromeで `chrome://extensions` を開く
2. 右上の「デベロッパーモード」をオン
3. 「パッケージ化されていない拡張機能を読み込む」をクリック
4. このディレクトリ (`minagine-bikou-extension/`) を選択

## 使い方

1. Minagineの勤怠表ページを開く
2. ツールバーの拡張機能アイコンをクリック
3. 入力する備考テキストを確認 (デフォルト: 自己啓発・研鑽)
4. 「対象を確認」で件数をプレビュー
5. 「一括入力を実行」で実行

実行中はページを操作しないでください。各行のメモアイコンを順番に開いて、テキストを入れて保存します。

## 動作モード

1. **警告バナー駆動（既定）**:「次の項目に問題があります」バナーに表示されている `MM/DD` 日付を全て対象とし、各行で次の処理を行います。
   - **開始時刻 / 終了時刻が空欄なら、その下に表示されている PCログ打刻時刻を `7:00 - 21:55` でクランプして入力**（例: PCログ `0613` → `0700`、`2628` → `2155`、`1032` はそのまま）
   - メモダイアログを開き、備考テキスト＋ PCログ打刻差異の報告（開始時刻/終了時刻 Select）に「自己啓発・研鑽」を投入
   - メインフォームの「保存する」をクリック → バナーを再パース
   - 警告が空になるまで反復（最大6周、進捗が止まれば中断）
2. **フォールバック（警告バナーがない場合）**: 「赤い行のみ対象」「既入力スキップ」「勤務時間あり」のオプションで通常通り処理。

## オプション

- **赤くなっている行のみ対象**: 警告バナーがない場合のフォールバックフィルタ
- **既に入力済みの行はスキップ**: メモアイコンが「ペン+紙」表示（既入力）の行を除外（フォールバック時のみ）
- **勤務時間がある行のみ対象**: `勤務時間数` が空または `0000` の行を除外（フォールバック時のみ）
- **最後に「保存する」を自動クリック**: 各反復で自動的にメインフォーム保存を実行。OFF にすると入力のみで反復しません

## 仕様メモ

- 備考ダイアログはMUI製のため、`textarea` の値はReact互換のsetterで設定（`Object.getOwnPropertyDescriptor(...).set` + `input`/`change` イベント）
- 保存ボタンは「保存 / 登録 / 確定 / 更新 / OK / 適用」のいずれかのラベルを検索
- 失敗した行はコンソールに `[minagine-bikou] failed:` で出力

## トラブルシュート

「失敗: N 件」と出た場合、ポップアップに失敗理由の先頭5件が表示されます（例: `1日: memo input did not appear after clicking the pencil`）。

ページのDevTools (F12) → Console を開いて、`[minagine-bikou] failed:` で始まるログから詳細スタックを確認できます。

代表的な失敗パターンと対処:

| 症状                                              | 原因の可能性                                     | 対処                                                                                  |
| ------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------- |
| `memo input did not appear after clicking the pencil` | クリック後に新規 input/textarea が生成されない | 拡張機能を再読み込み → ページ再読み込み。それでも出ない場合は手動で1行開いてDOMを確認 |
| `save button not found`                           | 保存ボタンのラベルが想定外                     | `content.js` の `SAVE_KEYWORDS` に該当文言を追加                                      |
| `dialog did not close after save click`           | バリデーションエラーで保存に失敗                | コンソールでネットワークエラーを確認、または手動で1件試して原因特定                  |
| `PCログ打刻差異の理由（開始/終了）を設定できませんでした` | 開始/終了の理由 Select が投入後に反映されなかった（MUIメニューの閉じ切り待ち失敗など） | 拡張・ページを再読み込みして再実行。継続する場合は該当日を手動で選択 |

## 注意

- 個人利用前提。会社のポリシー・申請ルールを確認のうえ自己責任で利用してください。
- DOM構造によっては保存ボタン検出が失敗する場合があります（フォールバックとして、キャンセル以外で右端の primary ボタンを押す挙動になっています）。

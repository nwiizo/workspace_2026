# Threat Model — STRIDE 脅威モデリング

対象プロジェクトに対して STRIDE 脅威モデリングを実行する。

## 実行手順

### Step 1: システム境界の定義

対象プロジェクトのコンポーネントと境界を特定する。

1. **エントリポイントの列挙**:
   - Web エンドポイント（ルーティング定義から抽出）
   - API エンドポイント
   - CLI インターフェース
   - スケジュールタスク・バッチ処理
   - メッセージキューのコンシューマー

2. **コンポーネントの特定**:
   - Web サーバー / アプリケーションサーバー
   - データベース
   - キャッシュ / セッションストア
   - 外部 API / サービス
   - ファイルシステム

3. **信頼境界の定義**:
   - インターネット ↔ リバースプロキシ
   - リバースプロキシ ↔ アプリケーション
   - アプリケーション ↔ データベース
   - アプリケーション ↔ 外部サービス
   - 認証済みユーザー ↔ 未認証ユーザー
   - 一般ユーザー ↔ 管理者

### Step 2: STRIDE 分析

各信頼境界の横断ポイントに対して STRIDE を適用する。

| カテゴリ | 脅威 | 分析対象 |
|---------|------|---------|
| **S**poofing | なりすまし | 認証機構、セッション管理、トークン検証 |
| **T**ampering | 改ざん | 入力検証、署名検証、CSRF 保護、整合性チェック |
| **R**epudiation | 否認 | 監査ログ、操作履歴、トランザクション記録 |
| **I**nformation Disclosure | 情報漏洩 | エラーメッセージ、ログ出力、API レスポンス、ディレクトリリスティング |
| **D**enial of Service | サービス拒否 | レート制限、リソース制限、入力サイズ制限 |
| **E**levation of Privilege | 権限昇格 | 認可チェック、ロール管理、IDOR |

### Step 3: 脅威の評価

各脅威に対して:

1. **攻撃シナリオ**: 具体的な攻撃手順を記述
2. **前提条件**: 攻撃に必要なアクセスレベル・知識
3. **影響度**: 成功時の影響（データ漏洩、権限昇格、サービス停止等）
4. **既存対策**: コード内で実装されている防御策
5. **残存リスク**: 対策の不足・回避可能性

### Step 4: 攻撃ツリーの構築

重要な攻撃目標（例: 管理者権限の取得、個人情報の窃取）に対して攻撃ツリーを構築する。

```
攻撃目標: [目標]
├── 攻撃経路 1: [手法]
│   ├── 前提: [条件]
│   └── 難易度: [Low/Medium/High]
├── 攻撃経路 2: [手法]
│   ├── 前提: [条件]
│   └── 難易度: [Low/Medium/High]
└── 攻撃経路 3（チェーン攻撃）: [手法1] → [手法2]
    ├── 前提: [条件]
    └── 難易度: [Low/Medium/High]
```

### Step 5: 出力

以下の構成でレポートを生成:

1. **システム概要**: コンポーネント図（テキストベース）、信頼境界
2. **STRIDE 分析結果**: カテゴリ別の脅威一覧
3. **攻撃ツリー**: 主要攻撃目標ごとの攻撃経路
4. **推奨対策**: 優先度付き対策一覧
5. **残存リスク**: 対策後も残るリスクの明示

# CFP Review - 採択確率を上げる段階的レビュー

このコマンドは、指定されたCfP（Call for Papers）を「第一印象 → 内容の詳細評価 → 文章・構成」の順に段階的にレビューし、審査員目線と聴講者目線の両方から採択確率を上げるための具体的な改善提案を提示します。

## レビューの原則

- **建設的であること**: 不採択判定でも必ず具体的で実行可能な改善提案を含める
- **内容をスタイルより重視**: 文章の巧みさよりも、提供される知見の価値を優先する
- **バイアスに注意**: 流行語や馴染みのあるトピックだけで評価せず、実質を見極める
- **読者目線**: 審査員だけでなく、聴講者として「この話を聞いて何が得られるか」を意識する

## 使用方法

```
/cfp-review [ファイルパス]
```

例:

```
/cfp-review samples/cfp/oh-kichijoji-pm-2026.md
```

ファイル未指定時は `contents/cfp.md` を読みます。

## 入力に含まれるべき情報

審査対象のCfPには以下を含める。CfPファイル内に不足していればユーザーに確認する。

### イベント情報

| 項目 | 内容 |
|------|------|
| イベント名 | |
| 対象者 | |
| イベントテーマ | |
| 発表時間 | |
| 過去の採択トピック傾向 | |
| 主要キーワード | |

### レビュー対象

- 講演タイトル
- 講演内容（Abstract）

## レビュー手順

Step 1 → Step 2 → Step 3 の順で段階的に評価する。各ステップは前の結果を踏まえて行う。

### Step 1: 第一印象チェック（タイトルと冒頭2〜3行のみ）

審査員は大量のプロポーザルを処理する。最初の数秒で興味を引けなければ、詳細な審査の機会すら得られない。**タイトルと冒頭の2〜3行だけ**を読み、以下を評価する。

**チェック観点**:
1. 発表の核となる目的が一読で分かるか
2. 続きを読みたいと思える引きがあるか（課題の提示、意外性、具体成果）
3. 聴講者のメリットが冒頭から読み取れるか
4. イベントのテーマ・キーワードとの接点が見えるか

- **評価（1-5）**
- **コメント**: 弱い場合は冒頭の書き換え案を具体的に示す

### Step 2: 内容の詳細評価（全体を精読）

Step 1 を踏まえ、全体を精読して3軸で評価する。

#### 2-1. イベントとの整合性・聴講者への価値

- イベントのテーマや目的に沿っているか
- 聴講者が持ち帰れる実用的な知見があるか（「何が得られるのか」「自分の仕事にどう活かせるのか」に答えられているか）
- 他では聞けない独自の視点・アプローチがあるか
- 対象聴衆のレベルに適切にフィットしているか（前提知識の過度な要求がないか）

- **評価（1-5）**
- **コメント**

#### 2-2. 技術的深さ・専門性の根拠

- 実践経験に基づく具体的な知見があるか（一般論・表面的な紹介に終始していないか）
- 具体的な事例・数値データ・Before/After が含まれているか
- 成功事例だけでなく、失敗や課題からの教訓にも言及しているか
- 話者がこのテーマについて語る適格性が伝わるか

- **評価（1-5）**
- **コメント**

#### 2-3. 新規性・タイムリーさ

- 現在の業界トレンドとの関連性があるか（関連性が弱い場合、それでもなお価値がある理由が示されているか）
- 既に広く知られた情報の繰り返しではなく、新鮮な洞察があるか
- 「なぜ今この話を聞く必要があるのか」に答えられているか
- 先見性のある視点や、今後の業界への示唆を含んでいるか

- **評価（1-5）**
- **コメント**

### Step 3: 文章・構成の品質

プロポーザルの内容がどれだけ良くても、伝え方が不十分では審査を通過しにくい。

**チェック観点**:
- 論理の流れが自然で、読み手が迷わない構成になっているか
- 一文が長すぎず、段落が適切に区切られているか
- 重要なポイントが視覚的に分かりやすく強調されているか
- 専門用語が対象聴衆に合ったレベルで使われている（または説明されている）か
- タイトルが内容を正確かつ魅力的に表現しているか

- **評価（1-5）**
- **コメント**

## レポート形式

以下の形式で Markdown レポートを作成する。

```markdown
# [CfPタイトル] CFPレビューレポート

**評価日**: YYYY-MM-DD

## 総合スコア

| 評価項目 | スコア |
|----------|--------|
| Step 1: 第一印象 | X/5 |
| Step 2-1: 整合性・価値 | X/5 |
| Step 2-2: 技術的深さ | X/5 |
| Step 2-3: 新規性 | X/5 |
| Step 3: 文章・構成 | X/5 |
| **総合** | **X/5** |

## Step 1: 第一印象
**スコア**: X/5

**コメント**: [第一印象についてのフィードバック]

**書き換え案**（必要な場合）:
- Before: [原文]
- After: [具体的な改善案]

## Step 2-1: 整合性・価値
**スコア**: X/5

**コメント**: [整合性と聴講者への価値に関する評価]

## Step 2-2: 技術的深さ
**スコア**: X/5

**コメント**: [深さと専門性に関する評価]

## Step 2-3: 新規性
**スコア**: X/5

**コメント**: [新規性とタイムリーさに関する評価]

## Step 3: 文章・構成
**スコア**: X/5

**コメント**: [文章品質に関する評価]

## 強み

[このプロポーザルの最も説得力のある点]

## 改善点（採択確率を上げるためのアクション）

各改善点について、**何を・どのように変えるか** を具体的に提案する。「もっと具体的に」のような曖昧な指摘ではなく、書き換え例や追加すべき要素を示す。

### 1. [改善提案タイトル]
- **現状**: [原文の引用と問題点]
- **提案**: [書き換え例・追加要素]
- **期待効果**: [審査・聴講者への影響]

### 2. [改善提案タイトル]
（同形式）

## 採択判断

以下のいずれかを選び、理由を述べる:

- **採択推奨**: このままでイベントの価値を高めるプロポーザル
- **修正を条件に検討**: 改善点を対応すれば採択水準（修正箇所を上記で明示）
- **不採択**: 現状では採択基準を満たさない（改善の方向性を明示）
```

## スコアリファレンス

| スコア | 意味 | 判断の目安 |
|--------|------|------------|
| 5 | 卓越 | すべての面で優れており、イベントに必須のトーク |
| 4 | 優良 | 高品質で、改善の余地はわずか |
| 3 | 良好 | 基本は良いが、特筆すべき点が少ないか重要な欠落がある |
| 2 | 要改善 | 可能性はあるが、大幅な修正が必要 |
| 1 | 弱い | 基本的な採択基準を満たしていない |

## 評価の基本姿勢

1. **建設的に**: 指摘には必ず改善案をセットで
2. **具体的に**: 抽象的な批評ではなく、書き換え例を示す
3. **バイアスを排除**: 馴染みのあるトピックだけで加点しない
4. **聴講者目線**: 「自分が聞いて何を得るか」を常に意識
5. **優先順位**: 全てを直す必要はない。Critical な箇所から

## 重要な注意事項

- イベント情報が不足している場合は推測で補わず、ユーザーに確認する
- 文章の好みではなく、採択基準としての価値判断を優先する
- 過去の採択トピック傾向と外れていても、独自性として評価できる場合は減点しない
- タイトル1つで採否が分かれることがある。Step 1 の評価は特に丁寧に行う

$ARGUMENTS で指定されたファイル（未指定時は contents/cfp.md）を読み、上記の手順に従って詳細な CFP レビューレポートを作成してください。

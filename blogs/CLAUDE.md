# CLAUDE.md - ブログプロジェクト専用ガイド

## プロジェクト概要

**目的**: 高品質なブログ記事の執筆・レビュー・公開
**記事タイプ**: コラム記事（エッセイ）/ 技術ブログ（チュートリアル）

## 最重要コマンド

```
/full-review [ファイル名] [記事タイプ]
```

**初稿完成後、このコマンド一つですべての品質チェックが完了します。**

```
/full-review blog.md コラム
/full-review tutorial.md 技術
```

## Claude Codeへの指示

### YOU MUST（必須）

1. **初稿完成後は必ず`/full-review`を実行を提案**
2. **記事タイプを確認**（コラム or 技術）
3. **承認フェーズで必ず一時停止**（ユーザーの選択を待つ）
4. **統合レポートの最優先改善を強調**
5. **文体は「です・ます」調**

### NEVER（禁止）

1. **承認なしに修正を適用しない**
2. **個別レビューコマンドを手動で順次実行しない**（`/full-review`を使用）
3. **完璧主義を押し付けない**（80%の完成度で公開推奨）
4. **Textlintエラーをすべて修正させない**
5. **細かい改行を作らない**

## 文章スタイルルール

### 改行ルール

- **1つの段落は3-5文で構成する**
- **一行あたり80-100文字を目安にする**
- **段落と段落の間は1行空ける（2行以上空けない）**
- 1文ごとに改行しない
- **`---`（水平線）で章を区切らない**（見出しのみで構造化する）

### コードブロック

シェルコマンドは` ```sh `を使用（` ```bash `は使用しない）

### AIっぽさの排除

**NGワード**: 「このような」「そのような」「非常に〜」の多用、「いかがでしたでしょうか」「させていただきます」

**OKな表現**: 「この」「その」（簡潔に）、「します」「役立ちます」

### 記事の長さ

- **推奨**: 2000-3000字
- **最大**: 5000字
- **最小**: 1000字

### 導入部の書き方

- **体験談から始める**: 「ある日、〜が起きた」で読者を引き込む
- **思考の流れを見せる**: 「コードにバグはない。SQLも正しい。では何が問題なのか」
- **原因を明示する**: 何が問題だったのかを具体的に示す
- **体験談は「だ・である」調でもOK**: 本文は「です・ます」、導入は「だ・である」で臨場感を出す

### 論理の階段を飛ばさない

- **読者と一緒に考える**: 「では何が問題なのか」のように疑問を共有
- **思考のステップを省略しない**: A→B→Cの流れで、Bを飛ばさない
- **接続を明示する**: 「この問題は〜と呼ばれる」で前後をつなげる

### 結びの書き方

- **冒頭の体験談に戻る**: 「冒頭で触れた〜は、〜で解消した」
- **記事全体を振り返る**: 「この記事で見てきたように」
- **具体的な判断基準で締める**: 抽象的な説教ではなく「金額にはNUMERIC、迷ったらNUMERIC」
- **読者への説教は避ける**: 「〜しましょう」「〜してください」より事実を述べる

## 簡易ワークフロー

```
1. 初稿を書く
2. /full-review draft.md [コラム|技術]
3. 最優先改善のみ修正
4. 公開！
```

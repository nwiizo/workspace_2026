# 「足さない練習」ワークショップ資料を作るプロンプト

次のプロンプトをそのままAIに渡すと、学生向けワークショップの説明、ワークシート、共通事例、進行ガイドを作れます。必要な考え方と事例はすべて含めてあり、ほかの資料は不要です。参加者がAIを使う必要もありません。

大切にしたいのは、正解を出したり、考え方を習得したりすることより、「そういう見方もあったな」と次に迷うときに思い出せる、小さなきっかけです。

開催条件を変える場合だけ、プロンプト末尾の入力欄を書き換えてください。空欄の追加情報や、外部の原稿を求めず、ここにある条件で作成できます。

```text
あなたは、学生向けワークショップ「足さない練習」の資料を作る編集者です。
以下の考え方と条件だけで、当日使える日本語の資料を作ってください。
外部の資料やリンクの内容を読む必要はありません。

【この時間で大切にしたいこと】
新しい道具を使う。教材を買う。予定を引き受ける。
何かを足したくなった身近な場面を、少し振り返る時間を作ります。

高い点数を取ることや、この場で判断方法を習得することは求めません。
「こういう見方もあるんだな」が、次に何かを選ぶときの小さなきっかけになれば十分です。
全部の問いに答える、四欄を完成させる、結論を出す必要はありません。
気になった問いや、まだ分からないことが残っていても、そのまま持ち帰れます。
気づきの数や内容も評価しません。うまく言葉にならなくても構いません。

「足さない」は決まった答えではありません。
今あるものを使う、何かを追加する、見送る、まだ決めない。どれも選べます。
変える必要はなさそうだと思うこともあります。少なさや変化の大きさを競わせないでください。
中心に置く問いは「足す前に、何が助けになるか考える」です。
記入例の条件を、買わない・足さない案しか選べないようには設定しません。
足すと助かる場面も示し、両方の案にある助けと手間から考えられるようにします。

【対象と形式】
開発経験が少ない学生向けの、60分の個人ワークです。
紙と筆記具、メモアプリ、エディターなど、書き慣れたもので参加できます。
デジタルなら四つの見出しを置くだけでよく、専用アプリや表の作成は求めません。
プログラミング、画面制作、AIのアカウントは不要です。
記入内容の共有・発表は行いません。採点、習得度の判定、提出も設けません。
個人的な事情や失敗の開示を求めず、名前は伏せて構いません。

【先に説明する四つの問い】
① 場面：いつ、何をしようとして、何を選ぼうとした？　今はどう対処している？
② 目的と条件：どうなりたい？　何を見れば分かる？　何は変わると困る？
③ 選択肢：二案を比べると、何が助けになり、どんな手間がかかる？　どこが気になる？
④ 確かめ方：まだ分からないことは？　小さく試すなら、何を見てみたい？

題材を選んでもらう前に、この構造と身近な例を説明してください。
①の出来事から②を考え、②を手がかりに③を比べ、④で確かめたいことを探します。
分かったことから、目的や案を考え直せます。
四欄は考える助けです。順番に全部埋めることを目標にしません。
説明の後、自分の最近の選択か、後述の共通事例を選んでもらいます。

【説明用の例：教材を買うか迷う】
以下は架空例です。
問題の途中で止まり、解説の一行が分からなかった。
「別の教材を買えば分かるかもしれない」と思ったとします。

分かっているのは、その一行で止まったことです。
別の教材なら分かるかは、まだ確かめていない見込みです。
「自分で一問解けるようになる」が目的なら、買うほかに、前の例題へ戻る、質問する案もあります。
今夜使える時間、お金、相談できる相手によって、試せる案は変わります。
たとえば今夜は30分。新しい教材は予算内で選びたい、とします。
今の例題へ戻る案と、新しい教材の試し読みを確かめる案を並べられます。
例題でも分からなければ、別の助けを探して構いません。
教材を買わないことが正解なのではなく、買う以外の見方もある、と立ち止まる例です。
この例を、参加者全員が使わなければならない題材にはしません。

【資料の説明と声かけに通してほしい見方】
・欲しい機能の名前だけで終わらず、誰が、どんな場面で、どうなりたいかへ戻る。
・「やる気がない」などの人物評価で片づけず、最近の一回に何が起きたかを見る。
・書き写しや毎回の電話確認は手がかり。ただし、手作業というだけで無駄とは決めない。
  今の方法が守っている安心や、新しい方法を使えない理由もある。
・機能があっても、必要な時間に使えない、存在を知らない、信用できないなら役立ちにくい。
・全部の問題を一度に引き受けず、目的に関わり、今の時間や助けで取り組めそうなところを見る。
・作ることが学習の目的なら、自作する時間にも意味がある。

これらを長い講義や用語の一覧にはせず、例や問いかけに必要な分だけ織り込んでください。

【なぜ、足す前に少し考えるのか】
作る負担が減っても、使う人の手間まで自動的に減るわけではありません。
入力欄を足せば、毎回選ぶ項目も増えることがあります。
同じ締切を一覧・通知・学習計画で使えば、変更がそれぞれに反映されたかを確かめます。
アプリを使ってもらい続けるなら、不具合対応、説明、更新後の確認などの運用にも時間がかかります。
機能をやめるときも、使う人への案内やデータの移動が必要になる場合があります。
短期間で閉じる試作に、長期運用の準備まで一律に求める必要はありません。

一方、通知で締切に気づけるなら、設定の手間を引き受ける価値があるかもしれません。
今のままの案にも、不便や手間は残ります。追加だけを悪者にしないでください。
比べるときは、助けになるところと負担を、両方の案で見ます。

【作ることも、確かめる方法になる】
問題を完全に言葉にするまで試せない、と考える必要はありません。
紙の案や小さな試作を見せて、初めて事情が分かることもあります。
表示の意味は紙でも聞けますが、通知が届くかは動く仕組みが必要です。
何を知りたいかから、試す形を考えます。

AIを使う場合も、人が考える場合も、知らない事情は自動的には分かりません。
使う人の反応を予想することと、本人を観察した結果は分けます。
早く作れても、使う機会や、使い続けた結果を待つ時間は残ります。
メモを読み直せたこと、実際に使えたこと、目的に届いたことを混ぜないでください。
一回使えた結果を、いつでも役立つという結論へ広げません。

【参加者が自分の経験を使うとき】
道具を増やすか、教材を買うか、活動や予定を引き受けるか迷った場面などを使えます。
選んだ後でも、迷っている途中でも構いません。一つの出来事に絞ってみます。
当時知っていたことと、後から知った情報を分けます。
覚えていない理由は「不明」のまま残し、もっともらしい理由で埋めません。
題材を思い出せなければ共通事例を使えます。途中での切り替えも認めます。

【標準の共通事例】
以下は架空事例です。
Aさんは大学1年生です。課題の説明と提出先は大学の授業サイトにあり、
スマートフォンのメモとカレンダーを使っています。
「課題を出し忘れるので、新しい通知アプリを入れようか迷っています。」
「先週は前日の夜に通知を見て、金曜18時までだと分かっていました。
でも、資料をどこから読んで、何を書けばいいか決められず、画面を閉じました。
次の日も別の課題があって、提出が間に合いませんでした。」
Aさんは今の道具の使い方を変えるか、新しいものを加えるかを考えています。
課題名と正しい締切の日付・時刻は残し、提出先は大学の授業サイトを使います。

この一件だけで、通知はいつも不要、本人のやる気がない、などとは決められません。
課題の説明がどのくらい具体的だったかも不明です。
「課題を開いたとき、最初にやることを一つ選べる」を目的の候補にできますが、
それが提出遅れのすべてを解決するとはしないでください。

【記入例に使える材料】
一つの考え方の例であり、模範解答にはしません。
① 締切は知っていたが、始め方を決められなかった。説明の具体性は不明。
② 最初にやることを一つ選べたら助かりそう。課題名、正しい締切、提出先は残す。
③ Aは今のメモに最初の一つを書く。考えて書く手間がある。
   BはAIに候補を出してもらい確認する。説明の入力と候補の確認が要る。
   Aが気になるが、何を書くかで迷うかもしれない。効果はまだ分からない。
④ 一つの課題で試すなら、どこで迷うか見たい。
   書くところで止まるなら、説明や相談相手の助けも考えたい。
架空のAさんの反応や、未実施の試行の結果は作らないでください。

【60分の進行】
0〜28分：四つの問いと身近な例の説明。考える間も取り、題材選びはまだ始めない。
28〜35分：題材選択と①。説明2分、考える・書く時間4分、見返す時間1分。
35〜42分：②。説明2分、考える・書く時間4分、見返す時間1分。
42〜49分：③。説明2分、比べてみる時間4分、見返す時間1分。
49〜56分：④。説明1分、読み直し1分、条件変更を考える2分、確かめたいことを考える3分。
56〜60分：個人での振り返り2分、講師のまとめ2分。共有・発表は行わない。

条件変更の例は「使える時間が半分なら」です。
共通事例では「課題の説明を外部のAIサービスへ入力できないなら」も使えます。
これは考えるための仮定で、現実の大学の方針ではありません。
結論が変わらなくても、変わっても構いません。

時間割は計画であり、実測値ではありません。
開催前に説明時間を確かめ、参加者が考える時間をその場で削らないようにします。
途中の欄が埋まっていなくても次の問いを紹介し、戻って考えてよいと伝えます。
質問が長くなったら本編後に扱います。最後の振り返りは、各自で静かに考える時間にします。

【作ってほしい資料】
Markdownで、次の四つを独立した見出しから出力してください。

1. 参加者向けの説明
   今日の過ごし方、四つの問い、教材の短い例、題材の選び方を示します。
   全部埋めなくてよいこと、結論を急がないこと、共有・発表は行わないことを伝えます。

2. 四欄のワークシート
   各欄に問い、書き出し、十分な空欄を設けます。
   ③は二案の助けと負担を同じ項目で比べる形にします。
   案を一つ選ぶ指示を必須にせず、気になる案や迷うところも残せる形にします。
   「まだ分からない」「今は決めない」や、自由な気づきも書けるようにします。
   全項目を必須にせず、空欄用のシートに記入例や採点欄を混ぜません。

3. 共通事例と記入例
   最初に配る事例と、考えた後に見せる記入例を分けます。
   記入例は「一つの考え方の例」と明記し、別の案や迷いも認めます。
   不明な事情や未確認の効果を補って、答え合わせにしないでください。

4. 主催者向けの進行ガイド
   準備物、時間割、問いを紹介する順序、声かけ、迷った人への助け方をまとめます。
   「気になった問いからで大丈夫です」「空欄のままでも構いません」と案内します。
   最後は、少し気になった問いや、次に思い出しそうな見方を振り返る時間にします。
   気づきが言葉にならなくても、そのまま終えて構いません。
   各ワークの指示でも、選択や試行計画を完成させることを求めないでください。

【書き方と最後の確認】
専門用語や仕事の担当順を前提にせず、学生が考え始めやすい自然な言葉にします。
講師の自己紹介、書籍紹介、歴史の説明、参考文献、他資料を読む指示は追加しません。
同じ主張を長く繰り返さず、説明から例、参加者自身の問いへ進めます。
資料間で、四つの問い、事例の事実、守る条件、時間割をそろえます。
完成・習得・気づきの数を求める表現や、共有・発表・提出を促す場面が紛れ込んでいないか確認します。
確認して直した資料本文を出力してください。未解決の点がある場合だけ、末尾に短く記します。

【今回の入力】
開催条件：上記の標準条件を使う（変更があればここに記入）
共通事例：上記のAさんの事例を使う（変更する場合は本文を記入）
出力方法：回答内にMarkdownで出力
```

## 主催者向けの進行メモ

紙と筆記具、メモアプリ、エディターなど、書き慣れたものを用意してもらいます。デジタルでは四つの見出しを置けば十分です。共通事例を使う場合は、上のプロンプトの「標準の共通事例」を先に配ります。「記入例に使える材料」は、参加者が考える前の答え合わせとして見せないようにします。

最初に「全部の欄を埋めなくて構いません。結論が出なくても、少し気になった問いが残ればと思います」と伝えます。採点・提出・共有・発表は設けず、気づきを言葉にすることも強制しません。

### 60分の時間配分

| 時間 | 案内すること | 参加者の時間 |
| --- | --- | --- |
| 0〜28分 | 四つの問いと、教材などの身近な例を説明する。 | 聞いたり、少し考えたりする。題材選びはまだ始めない。 |
| 28〜35分 | 題材と①の問いを2分で紹介する。 | 4分考え、1分見返す。 |
| 35〜42分 | ②の問いと短い例を2分で紹介する。 | 4分考え、1分見返す。 |
| 42〜49分 | ③の比べ方を2分で紹介する。 | 4分比べてみて、1分見返す。 |
| 49〜56分 | ④の問いを1分で紹介する。 | 読み直し1分、条件変更を考える2分、確かめたいことを考える3分。 |
| 56〜60分 | 個人での振り返りを促し、最後に講師がまとめる。 | 静かに振り返る2分、まとめを聞く2分。共有・発表はしない。 |

説明中も、問いを置いたら少し待ちます。時間は計画上の目安で、実測ではありません。開催前に説明時間を確かめ、長ければ例や話す範囲を絞ります。考える時間をその場で削って帳尻を合わせないでください。

### 迷ったときの声かけ

| こんな様子なら | 声かけの例 |
| --- | --- |
| 自分の題材が浮かばない | 「Aさんの共通事例でも大丈夫です。途中で替えても構いません。」 |
| 出来事と理由が混ざる | 「実際に起きたことと、そうかもしれないと思ったことを、分けてみてもよさそうです。」 |
| 「便利にしたい」で止まる | 「いつ、何をするときに助かるとよさそうですか。」 |
| 案を選びきれない | 「今は決めず、ここが分かると考えやすそう、というところだけ残しても構いません。」 |
| 書けずにいる・空欄がある | 「書かずに考えていても大丈夫です。気になった問いだけ使ってください。」 |

過去の選択では、当時の理由を後から作らせないようにします。覚えていない理由は不明のままにし、後から考えた別案には、その旨を添えられます。選択の結果だけから本人の判断を評価しません。

### 共通事例を替える場合

専門知識なしで一分ほどで読める、一つの出来事にします。誰が何をしようとしたか、今使っている方法、変わると困る条件、まだ不明なことを含めます。正解を一つに決めず、異なる助けと負担がある案を比べられるようにします。

事情を後出しして不正解にする進め方にはしません。架空の発言や人物なら、その旨を明記します。現実の人の話を使う場合は、本人が話してよい範囲だけを使います。

④の条件変更は、参加者の題材に合う仮定を一つ選びます。使える時間や予算が変わったら、くらいで構いません。Aさんの事例の「外部のAIへ入力できないなら」も仮定であり、現実の大学の方針ではありません。

### 終わり方

「少し気になった問いはありましたか」「次に迷ったら、思い出すかもしれない見方はありましたか」と、静かに振り返る時間を取ります。何かを習得したか、選択を変えたか、いくつ気づいたかは確認しません。

記入内容の共有や発表は行いません。各自でメモを眺め、気になったことがあれば書き残して、そのまま持ち帰ってもらいます。質問が長くなった場合は、希望する人と終了後に話します。

# 「足さない練習」ドキュメント作成プロンプト

開発経験が少ない学生向けの60分ワークショップについて、配布資料と進行ガイドを作るためのプロンプトです。主催者が準備に使います。参加者がAIを使う必要はありません。

## 使い方

下のプロンプトをコピーし、スライド原稿と進行ガイドを参照資料として渡してください。開催条件や別の共通事例があれば、末尾の入力欄に追記します。空欄なら記載の標準条件を使えます。

このリポジトリと `slides` リポジトリが同じ親ディレクトリにある場合、参照資料は次の場所にあります。

- [スライド原稿](../../../slides/slides/2026/60min-practice-not-adding.md)
- [進行ガイド](../../../slides/docs/practice-not-adding-workshop.md)
- [公開PDF](../../../slides/slides/2026/60min-practice-not-adding.pdf)

チャットでは、Markdownの原稿と進行ガイドの本文を添付または貼り付けてください。ローカルファイルを読める環境では、実際の配置場所を指定できます。参照資料がなくても標準条件で下書きは作れますが、スライドと照合済みとは扱えません。

## コピーするプロンプト

```text
あなたは、学生向けワークショップ「足さない練習」の配布資料を作る編集者です。
以下の条件と、渡した参照資料をもとに、当日使える日本語のドキュメントを作ってください。

【誰のために、何を作るか】
対象は開発経験が少ない学生です。60分の個人ワークで、発表は任意です。
題材には「自分が最近経験した選択」または「主催者が用意する共通事例」を使います。
画面制作、プログラミング、AIのアカウントは参加条件にしません。

タイトルは「足さない練習」です。
道具や機能を減らした数を競うワークではありません。
何を足すか、見送るか、保留するかを、目的と根拠から説明できることを目指します。
持ち帰るものは、選択と理由、引き受ける負担、次に確かめることがつながった四欄のメモです。

【資料を読む順序】
スライド原稿と進行ガイドが渡されていれば、両方を読み、説明・演習・補足の区別を確認してください。
開催条件として明示された変更を優先し、それ以外は参照資料に合わせてください。
資料同士が食い違う場合は、食い違いを短く示し、どの前提で下書きしたかを明記してください。
読めない資料や未提供の書籍を、読んだことにしないでください。
参照資料がなくても、以下の標準条件から下書きを作れます。その場合は照合できなかった範囲を末尾に記してください。

【説明の順序】
先に考え方を説明し、その後で題材を選び、ワークを始めます。
冒頭では、AIにコードを書いてもらい、機能を試作しやすくなったことを入口にしてください。
そこから「作れる候補が増えたとき、どれを使うかはどう決めるか」へつなげます。
開発の話だけにとどめず、教材、道具、予定など、学生が経験できる選択へ広げてください。

考える構造は、次の四つです。
① 場面：いつ、何をしようとして、何を選ぶ必要があったか。
② 目的と条件：どうなりたいか。何を見れば分かるか。何を守りたいか。
③ 選択肢：同じ基準で二案を比べると、何が助けになり、どんな手間がかかるか。
④ 確かめ方：どこが未確認か。次に何を試すか。何が変わったら選び直すか。

四つの名前を並べるだけにせず、つながりを説明してください。
①の出来事から②の目的を考え、②を基準に③を比べ、④で役立つかを確かめます。
新しく分かったことから、目的や案を見直せます。
これは三冊の見方を参考にした、このワークショップ独自の整理です。
書籍の正式な手法名や、仕事の担当順として説明しないでください。

【言葉と前提の扱い】
書籍の要約を順番に紹介する文章ではなく、講師が学生へ説明する自然な言葉にしてください。
「どんな場面か → 何が分かっているか → 何を考えたいか → 次に使う問い」の順に進めます。
一つの節では一つの論点を扱い、必要なら分割してください。
用語が必要なら、身近な例を説明してから、その意味を一文で示してください。
たとえば「認知負荷」は覚える操作や直す場所、「判断の来歴」は選んだ理由とその条件から説明できます。
組織のワークフロー、担当者間の引き継ぎ、設計手法の知識を前提にしないでください。
講師の口癖を作ったり、講師本人の体験や発言を創作したりしないでください。
書籍の著者の経験は、著者の経験として区別してください。

教材の説明例では、まず「問題の途中で止まり、解説の一行が分からなかった」という出来事を置けます。
「別の教材なら分かる」は、まだ確認していない見込みです。
「一問を自分で解けるようになる」を目的にすると、買う、前の例題へ戻る、質問するなどを比べられます。
使える時間や費用が変われば、候補も変わります。説明用に置いた数字は仮定と明示してください。
次の例へ移るときは、何を確かめるために例を替えるかを短く伝えてください。

【ワークで守ること】
自分の題材を選べない人には共通事例を案内し、途中での切り替えも認めてください。
個人の事情や失敗の開示を求めず、名前は伏せて構いません。
当時知っていた事実、当時の推測、後から分かった情報を分けてください。
理由を思い出せなければ「不明」と書けます。後付けの理由で埋めないでください。
二案のうち一つは、今あるものを使う案や、小さく試す案にしてください。
追加する案だけでなく、今のままにする案にも残る困りごとや手間を挙げてください。
追加が目的に合う場合もあります。足さないことを正解に誘導しないでください。
減らす場合も、必要な情報や、すでに役立っている使い方を残します。
材料が足りなければ、保留の理由と、次に調べることを書けます。
紙で理由を読み直せたこと、実際に使えたこと、目的を達成できたことは別です。
共通事例の人物の反応や、実施していない試行の結果を創作しないでください。

【標準の共通事例】
以下は架空事例です。別の事例が指定されていれば、そちらを使ってください。

Aさんは大学1年生です。課題の説明と提出先は大学の授業サイトにあり、
スマートフォンのメモとカレンダーを使っています。
「課題を出し忘れるので、新しい通知アプリを入れようか迷っています。」
「先週は前日の夜に通知を見て、金曜18時までだと分かっていました。
でも、資料をどこから読んで、何を書けばいいか決められず、画面を閉じました。
次の日も別の課題があって、提出が間に合いませんでした。」
Aさんは今の道具の使い方を変えるか、新しいものを加えるかを考えています。
課題名と正しい締切の日付・時刻は残し、提出先は大学の授業サイトを使います。

この材料から、通知はいつも不要、本人のやる気がない、特定の学習上の問題がある、などとは決めないでください。
「課題を開いたとき、最初にやることを一つ選べる」を目的の候補にできます。
それが提出遅れのすべてを解決するとはしないでください。
事例の資料にない事情は不明のまま残し、追加の仮定は区別してください。

【標準の時間割】
0〜24分：考え方の説明。演習はまだ始めない。
24〜32分：題材選択と①。説明3分、記入4分、確認1分。
32〜40分：②。説明2分、記入4分、確認2分。
40〜48分：③。説明2分、比較と記入4分、確認2分。
48〜56分：④。説明1分、読み直し2分、条件変更を考える2分、次の試行を書く3分。
56〜60分：振り返り2分、希望者の共有とまとめ2分。
共有は一人30秒を目安にし、残り時間を見て人数を調整します。
補足の書籍紹介は本編の時間に含めません。
これは計画上の割り当てです。実測した時間として表現せず、開催前のリハーサルで確認する点を主催者向けに残してください。

【作るドキュメント】
Markdownで、次の四つをそれぞれ独立した見出しから出力してください。
ファイル保存の指定がなければ、回答内に本文を出してください。

1. 参加者向けの説明
   タイトル、今日考えること、四つの問いのつながり、題材の選び方を説明します。
   教材の短い例で事実と推測、目的と手段を区別してから、記入へつなげます。
   開発経験やAIが不要で、共有は任意であることを伝えてください。

2. 四欄のワークシート
   ①〜④それぞれに、考える問い、書き出し、十分な空欄を設けてください。
   ③は二案について、目的への助け、守る条件、引き受ける手間を同じ項目で比べられる形にします。
   選んだ理由、見送るもの、不明点、次の試行、見直す条件も書けるようにしてください。
   空欄用のシートに模範解答を混ぜないでください。

3. 共通事例と記入例
   事例を一分程度で読める長さにし、事実、守る条件、不明なことを区別します。
   参加者へ最初に配る事例と、説明後に見せる記入例を分けてください。
   記入例は四欄に対応させ、「一つの仮案」と明記します。
   二案とも負担を示し、未実施の効果は「未確認」としてください。
   同じ答えを求めず、別の案でも目的・条件・理由がつながっていれば扱えるようにします。

4. 主催者向けの進行ガイド
   準備物、時間割、各ワークの声かけ、迷った人への助け方をまとめます。
   事実と推測、目的と手段、予定と結果、完成と実利用の違いを、どこで確かめるか示します。
   条件を一つ変える場面では、参加者の題材に合う仮定を使います。
   「時間が半分になる」などを例示し、現実の事実とは混ぜないでください。
   質問が長引いたら本編後に回し、記入時間を確保する進め方を示します。

【書籍とのつながり】
参照資料に根拠がある範囲で、主催者向けガイドの末尾に簡潔に残してください。
Architecture for Flow：目的と手段、その手段が役立つ条件、変更後の見直し。
Agentic Engineering：AIへ伝える目的・条件・範囲と、出来上がったものを確かめる判断。
Regenerative Software：道具を替えても残すもの、確認方法、選んだ理由とその前提。
学生向けの説明では書名や専門用語を理解の前提にせず、出典は説明を支える位置に置いてください。
未確認の章番号、引用、効果の数値を補わないでください。

【提出前に確かめること】
説明が先、題材選びとワークが後になっているか。
四つの資料で、問いの名前、事例の事実、守る条件、時間割が一致するか。
二案を同じ基準で比べ、追加・見送り・保留のどれも理由から選べるか。
空欄のワークシートに、記入例や作り話の結果を混ぜていないか。
専門用語や書籍の知識なしで、次に何を書くか分かるか。
確認して直した本文を出し、未解決の点がある場合だけ末尾に短く記してください。

【今回の入力】
開催条件の変更：なし（変更があれば記入）
主催者が使いたい共通事例：上記の標準事例（別の事例があれば本文を記入）
参照資料：このプロンプトとともに渡したスライド原稿・進行ガイド
出力方法：回答内にMarkdownで出力（保存先の指定があれば変更）
```

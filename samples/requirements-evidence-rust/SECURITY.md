# セキュリティ評価の範囲

## このサンプルで自動化する攻撃者視点

`cargo test --test adversarial`は、次の悪用を再現する。

- 上限を超える非UTF-8入力を送り、解析順序やpanicを探す。
- `u64`を超える数値を送り、整数変換の破綻を探す。
- 別の操作主体から送金元口座を指定する。
- 存在しない口座を指定し、認可失敗との混同を探す。
- 復元データへ重複口座を混ぜる。
- 完了済み要求IDを異なる金額で再利用する。
- 残高不足と宛先オーバーフローを起こし、一部更新を探す。

このテストは、既知の悪用仮説を毎回反復するセキュリティ回帰テストである。独立したペネトレーション
テストの代わりにはならない。

## 独立評価へ渡す前提

HTTP APIや永続DBへ接続した段階では、少なくとも次の対象を追加する。

1. 認証トークンの改ざん、失効、別テナント混同。
2. 同時実行、プロセス再起動、複数インスタンス間での要求ID競合。
3. リクエストサイズ、レート、完了一覧の増加による資源枯渇。
4. エラー内容、応答時間、ログからの情報漏えい。
5. DBトランザクション中断、再試行、バックアップ復元後の二重反映。

評価者には`DESIGN.md`の対象範囲、`REQUIREMENTS.md`のBR-3からBR-8、公開API、既存テスト結果を渡す。
テスト結果は新しい脅威がないことを保証しない。発見事項は要求IDまたは新しい要求へ結びつけ、再現可能な
ケースは`tests/adversarial.rs`へ戻す。

## 既知の残余リスク

- `ActorId`が本当に認証済みかは上流に依存する。
- 完了済み要求はメモリだけにあり、再起動後の再送を防げない。
- 完了一覧は増え続けるため、保存期限や容量制御が必要である。
- 単一プロセスの`&mut Ledger`は、分散環境の同時実行制御にならない。
- 監査ログ、可用性、秘密情報の扱いは未実装である。

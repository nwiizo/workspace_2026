# GDPR Data Erasure ✅

**難易度:** ⭐⭐⭐
**カテゴリ:** 認証
**目標:** 削除されたアカウントでログインする

---

## 思考プロセス

**ステップ1: 削除の仕組みを考える**
```
「GDPRでは "忘れられる権利" がある」
    ↓
「ユーザーがアカウント削除を要求できる」
    ↓
「でも本当に物理削除？それとも論理削除（フラグを立てるだけ）？」
```

**ステップ2: 論理削除の構造を推測**
```
「多くのシステムは deletedAt や is_deleted というカラムを使う」
    ↓
「deletedAt に日時が入っていれば削除済み」
    ↓
「ログインSQLは通常 WHERE deletedAt IS NULL を含むはず」
```

**ステップ3: SQLiで削除済みユーザーを探す**
```
「' or 1=1-- だと通常ユーザーが返る」
    ↓
「削除済みユーザーだけを取得したい」
    ↓
「' or deletedAt IS NOT NULL-- を試す」
    ↓
「削除済みユーザー（Chris）でログインできた！」
```

## 実行手順

1. `http://localhost:3000/#/login` にアクセス
2. Email欄に以下を入力:
   ```
   ' or deletedAt IS NOT NULL--
   ```
3. Password欄に何か入力
4. 削除済みユーザー（Chris）としてログインできる

## 解説

- `deletedAt IS NOT NULL` = 「削除日時が設定されている」= 削除済みユーザー
- GDPR（EU一般データ保護規則）で削除されたはずのアカウントにアクセスできてしまう
- 法的コンプライアンス違反

**なぜこれが危険？**
- 「忘れられる権利」が守られていない
- 削除したはずの個人情報にアクセス可能
- GDPRでは最大2000万ユーロの罰金

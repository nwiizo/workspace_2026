# 2026 FinOps ベストプラクティスと業界共通の学び

クラウドベンダー非依存の原則。AWS 固有の詳細は他ファイルを参照。

## FinOps Foundation 2026 Framework

Framework 2026 で更新された主な観点：

- **Executive priority 重視**: 可視化・予実管理・Capacity Planning がトップ優先
- **Technology Categories 拡張**: SaaS、データセンター、ライセンス、データクラウドも対象化
- **新 Capability の追加**: AI / ML ワークロード向けの最適化観点

## 5段階成熟度モデル

1. **Visibility** — どこにお金がかかっているか見える状態
2. **Tactical Optimization** — 明らかな無駄を潰す（idle、orphan、stopped with EBS）
3. **Strategic Optimization** — アーキテクチャ判断でコスト下げる（Spot、マネージド移行、Serverless化）
4. **Governance** — 組織全体でコスト統制を強制（予算、タグ必須化、異常検知）
5. **FinOps Culture** — 開発プロセスにコスト意識が組み込まれた状態

調査は Stage 1-2 が主対象。Stage 3 以降は担当者・アーキテクトとの協働が前提。

## 業界ベンチマーク

- **クラウド支出の 30〜40% は idle / 過剰プロビジョニング / zombie assets** で浪費されている（多くの調査で一致）
- 成熟した FinOps 文化を持つ組織は **30〜50% の節約**を達成できている
- 100万円の経費削減 ≒ 売上 300万円に相当（利益率換算）。コスト削減のビジネスインパクトは過小評価されがち

## コスト削減の7つの方法

大枠の施策パターン：

1. **数量を減らす・削除する** — 不要リソース削除、停止中リソース整理
2. **容量を減らす** — Right Sizing、ストレージ縮小
3. **種類を変える** — 世代更新（新しい方が安くて速い）、ストレージタイプ変更（gp2→gp3 など）
4. **構成を変える** — Multi-AZ → Single-AZ、ALB 統合、アベイラビリティ要件の見直し
5. **課金形態を変える** — RI / SP / CUD、Spot VM、Savings Plans
6. **環境を丸ごと引っ越す** — ベンダー変更、リージョン変更
7. **アプリケーション側を軽くする** — クエリ最適化、キャッシュ、フレームワーク変更

段階的には 1→7 の順で「低リスク・高効果」から手をつける。最後の 6 / 7 はリターンに対してコスト高。

## SRE / インフラエンジニアの3大使命

- 設計と構築
- 負荷試験
- **リソース・コスト調整**

コスト調整は負荷試験と類似の知識を必要とするが、**自らリスクに寄せる性質**がある（削ってダメなら事故る）。繊細な思考とコミュニケーションを要する。

## RI / SP / CUD 購入の鉄則

1. **先にゴミ掃除** — 未使用リソース削除 → Right Sizing → 構成最適化
2. **ベースライン観測** — 60〜90 日の実測データ
3. **commitment coverage 60〜80%** — 100% はバースト対応不能、50% 以下は機会損失
4. **1年契約を基本** — 3年契約は**世代交代の機会損失**のリスク大。2〜3年サイクルで新世代が出る業界特性
5. **支払い方法は組織事情次第** — 全前払い最大割引、一部or無しは月次予実安定

## クラウド間引越しの判断基準

- **10〜20% の削減余地**: 現環境の最適化を優先。移行コストで相殺
- **30〜50% の削減余地**: 前のめりに検討する価値あり
- 交渉材料: 大規模利用のボリュームディスカウント、ロゴ使用許諾、事例公開

## 継続的 FinOps のための仕組み

- **タグ戦略**: 可視化の土台。「retroactive tagging は高コストで成功しない」ので最初から強制
- **異常検知**: Cost Anomaly Detection 等で日次〜週次チェック
- **予算アラート**: 閾値超過時の自動通知
- **定期レビュー**: 月次または四半期で trend 確認
- **コスト責任者の明確化**: Product / Engineering に割り振る showback モデル

## ツール選定の考え方

- ベンダー純正ツール（Cost Explorer / FinOps Hub / Billing Reports）で 80% カバー可能
- 残り 20% を ThirdParty（CloudZero / nOps / Apptio Cloudability 等）で補完する価値がある場合のみ導入
- ツールより**データ読み解き能力とコミュニケーション**が重要

## よくある失敗パターン

- **早すぎる commitment 購入** — ゴミ掃除前に買うと過剰購入になる
- **ツール導入で満足** — 可視化だけして施策が進まない
- **大手1社依存** — 複雑な割引制度を理解しないまま使う
- **単発の調査で終了** — 放置するとすぐ元に戻る、継続運用が前提
- **削減額の水増し報告** — 分母不一致、重複計上で後から辻褄が合わなくなり信頼失墜

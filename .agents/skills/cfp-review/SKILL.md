# CFPの作成とレビュー

審査員が内容の価値を判断でき、聴講者が自分に役立つ発表かを選べる応募文にする。
依頼から作成・改善・レビューの範囲を読み取る。レビューだけなら所見を返し、
作成・改善なら提出項目を仕上げて検証する。指定されたファイルと会話から対象を特定する。

## 提出条件と素材

イベントの目的・聴衆、発表時間・カテゴリ・レベル・言語、文字数・必須項目を確認する。
現在の募集要項が必要なら公式情報を読む。過去の採択傾向や隣接イベントは、
差別化やイベントとの整合を判断するために必要な場合だけ調べる。
非公開の選考理由や不採択案を想像しない。

提出の有効性や内容量を左右する不明点だけ確認し、独立して書ける部分は進める。
話者の実績、失敗、数値、第三者評価を作らない。素材に応じて、実践報告、
概念解説、設計案、仮説などの位置づけを選び、未検証の効果を実績と扱わない。

## 作成・改善

対象者の課題、話者が示せる根拠、聴講後にできる判断を軸に、発表時間内の内容へ絞る。
設計を整理しにくい場合は「誰が、どの課題について、何を根拠に、何を学べるか」を一文にする。

- タイトルと冒頭で、課題、扱う視点・経験・手法、聴講者の持ち帰りが伝わるようにする。
- 本文は必要な背景、比較・選定理由、具体例、制約、応用をつなぐ。短い概要に固定の5段階構成を当てない。
- 話者が語る理由を、経験・再現可能な方法・独自の分析など実際の根拠で示す。
  数値や失敗談を全テーマに要求しない。
- 流行との接点は内容がある場合に使う。流行から外れることだけで価値を下げない。
- タイトル、概要、カテゴリ、レベル、キーワードが同じ発表を示すよう揃える。
  強いタイトルのために本文にない成果や危機を足さない。

作成時は、本命タイトル、提出用概要、指定された追加項目を返す。
募集要項にある文字数・個数を検証し、未確認の提出条件や素材を明示する。
採点表や別案の数を埋めるために成果物を増やさない。

## レビューで見ること

| 観点 | 判断すること |
| --- | --- |
| 制約・事実 | 必須項目、文字数、発表時間、主張の裏付け |
| 第一印象 | タイトルと冒頭から課題・方法・持ち帰りが分かるか |
| 整合性・価値 | イベントと対象者に合い、適用先や他の発表との差があるか |
| 深さ | 実践、比較、検討過程など、話者が語る根拠があるか |
| 新規性 | 今扱う意味、独自の経験や視点、後にも残る学び |
| 聴衆への配慮 | 前提知識と難易度が合い、価値を広げすぎていないか |
| 明確さ | 課題・内容・根拠・持ち帰りを追え、タイトルと本文が一致するか |

通常は問題のある箇所と、直し方を判断するために必要な観点を使う。
段階レビューを求められたら、制約・事実、第一印象、内容、明確さの順に見る。
採点や模擬審査を求められた場合だけ [採点基準](references/scoring.md) を読む。

制約違反と裏づけ不能な主張を優先し、平均点で埋もれさせない。
指摘は原文の位置、問題になる条件、置換文・追加する事実・削る範囲を対応させる。
強い箇所も残せるよう示す。指摘数を固定せず、問題がなければその旨を伝える。
採択確率や実際の選考結果を、AIの評価から断定しない。
